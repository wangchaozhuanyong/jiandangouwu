# CloudBridge 项目开发规则

本文件是当前项目的最高级开发入口。项目路径固定为 `/Users/wangchao/Desktop/源码文件夹/简易购物网站`；它是独立项目，不得直接套用其他网站的业务模型、目录、接口、数据库、角色或部署方案。

## 项目现状与技术栈

- CloudBridge 已收口为 Sites-only：`apps/sites` 是唯一生产 Worker，`apps/storefront` 和 `apps/admin` 作为其前端源码，`packages/contracts` 保存共享类型。
- 生产结构化数据使用 Sites D1，媒体使用 Sites R2，管理员身份由 ChatGPT 托管；不再维护 MySQL、Valkey、Prisma、Docker Compose 或 AWS CDK。
- 根目录 `src/` 是 Sites 兼容界面与设计基线，仍被根构建和发布测试引用，不得误删。
- Node.js 基线为 24.x，npm 11.x，依赖由 `package-lock.json` 锁定。
- 金额、汇率和订单价格通过十进制字符串与整数运算处理，禁止 JavaScript 二进制浮点参与业务计算。
- 不默认引入新的 UI 框架、支付或第三方集成；修改部署、身份、数据库结构或新增大型依赖前仍须确认。

## 能力真实性

- Sites 已实现商品、分类、轮播、币种、联系方式、人工订单、审计、D1 备份、Telegram 可靠投递、自动汇率和数据治理工作流。
- Telegram 只有在生产密钥存在且真实 `getMe`、`getChat`、`sendMessage` 验证成功后才允许有效启用。
- 汇率法币来自 ECB，USDT/MYR 来自 Coinbase；陈旧或异常批次失败关闭下单，但不阻断公开浏览。
- 数据保留当前只提供清理预览，自动删除保持关闭；隐私请求和密钥轮换必须有原因、确认与审计。
- 在线支付、自有域名、无人确认的 D1 自动切换、邮件邀请投递和跨账号会话仍未开发。当前员工能力是 CloudBridge 内部精确邮箱预授权，不等于已发送邀请邮件或 ChatGPT 跨账号会话。
- 本地构建或测试成功不代表已发布；只有 Sites 已保存版本、生产部署状态和匿名浏览证据可证明上线。
- 文档和交付报告必须明确区分“当前已实现”“当前模拟”“未来规划”，缺少真实证据时不得写成“已接通”“已发布”或“生产可用”。
- 长任务、外部操作和保存动作必须依据真实执行状态展示结果，禁止用计时器或前端状态直接伪造成功。

## 开发与变更边界

- 开始修改前先阅读本文件、相关 `docs/` 文档、`package.json`、目标源码和对应测试。
- 每次只处理清晰、可验收的任务；优先最小范围修改，不重构无关文件，不删除用户资源。
- 代码标识、接口字段和未来数据库字段使用英文；需求和规则文档以简体中文为主；可见界面文案必须提供完整的 `{ zh, en }`。
- 金额不得使用二进制浮点进行业务计算。API 使用十进制字符串，汇率换算使用整数运算。
- 业务状态使用稳定枚举码，样式和流程不得依赖中文或英文显示文案。
- 新增环境变量时必须同步 `.env.example`；`VITE_` 前缀变量视为公开信息，不得放入密钥、Token、密码或私有地址。
- 不得擅自初始化 Git、提交、推送、创建 PR、部署或修改生产环境。

## 工作流与完成定义

1. 在 `docs/ROADMAP.md` 中确认任务范围、依赖、风险和验收标准。
2. 修改前复核当前实现；涉及接口、数据库、登录、支付、部署或新增大型依赖时先请求确认。
3. 实现加载、错误、空状态、表单校验、移动端和基础无障碍，并补充与风险匹配的测试。
4. 至少运行受影响测试；交付前运行 `npm run check`。
5. 完成报告必须列出改动内容、修改文件、检查命令与结果、未验证风险和后续事项。

## Sites 运行与交付

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

保持 `.openai/hosting.json`、`worker/index.js`、`scripts/prepare-sites-build.mjs`、`scripts/prepare-sites-platform-release.mjs` 和 `tests/sites-worker.test.mjs` 完整。D1 结构变更使用 `apps/sites/drizzle/` 中已审查迁移。Sites 交付前运行 `npm run check` 与 `npm run build:sites`。

## Durable CloudBridge design decisions

- The selected formal storefront visual direction is option 2, "瓷白双港": a cool porcelain canvas paired with deep-navy image-led anchors, restrained cyan bridge lines, editorial type, premium product art, and quiet, intentional motion. It is the light-theme and formal component visual baseline; the paired deep-navy "夜航画廊" theme remains supported and remains the default.
- The option-2 implementation remains a UI-only visual mapping for preview surfaces. Phase one may now preview an in-memory cart, but preview routes must not create a server order, persist cart state, add quantity controls, collect payment, or claim checkout success. The owner has separately authorized the formal distinct-item manual-order foundation: shared contracts, additive D1 `order_items`, server-priced multi-item order creation, high-entropy order numbers, and the rate-limited `POST` order-number lookup may exist in formal code. This authorization does not include quantities, persisted or cross-device cart state, accounts, payment, automatic fulfillment, unsafe enumerable lookup, production navigation changes, or deployment. Contact lookup remains blocked until an ownership-verification channel is separately designed and approved.
- V2 work uses three explicit truth levels: current production-backed behavior, phase-one interface preview, and phase-two-or-later formal implementation. A phase-one preview must carry a persistent bilingual `界面设计预览 / Interface design preview` notice, use mock or read-only data, state that server data is unchanged, and never be reported as a released route, saved setting, connected integration, or completed business capability.
- V2 keeps site navigation and catalog navigation as separate layers. The desktop website header contains the CloudBridge brand, Home and Skill recommendations, plus order lookup, theme, language, support, and cart utilities. Transit subscriptions and AI recharge are product catalog surfaces, not duplicate website navigation. The catalog uses exactly two category levels: a pure-text primary row above the products and a secondary text rail to the left of the product results. `全部商品 / All products` is a storefront-only virtual entry and is not stored as category data; every DEMO product and every future formal product ultimately belongs to one secondary category. Product details remain immersive and render neither the global header nor either category level. The home-only transit shortcut uses the selected 56px `环桥圆章 / Ring bridge seal` direction, with the complete `中转站 / Transit` label inside the circular control; it must not become a rectangle, elongated capsule, or unlabeled circle.
- At 760px and below, the compact header keeps the real transparent-background logo and wordmark plus theme, direct language toggle, and support; it stays fixed at the viewport top while retaining its normal layout space, and it does not show a top-right cart control. The fixed safe-area-aware bottom navigation contains exactly four complete entries in this order: Home, Skill recommendations, Cart, and Order lookup. Cart navigates to a dedicated preview page rather than opening a mobile popup. Product search and the smaller currency control share one toolbar row; the pure-text primary category row sits directly below it, and both stick below the compact header once reached. Secondary categories use a compact 72–76px icon-free text rail on the left; Chinese labels must display four characters without clipping. The secondary frame sizes to its actual rows, which stay top-aligned at a 48px touch-height floor and never stretch to fill the product viewport; only overflowing category sets scroll internally. The right side uses horizontal product rows whose full copy/action block never exceeds the product-image height.
- Phase one continues to preview Home, Skill recommendations, Transit and AI catalog surfaces, a three-mode DEMO lookup, and an in-memory distinct-product cart. The formal foundation now supports server-priced distinct-item manual orders and complete high-entropy order-number lookup with HMAC-only rate-limit records, uniform failures and `no-store`, but no formal storefront route has been connected or deployed yet. `本机订单 / On this device` remains a client-owned safe summary; `联系方式 / Purchase contact` remains DEMO-only until ownership verification exists. Preview routes must still use DEMO data, must not call formal order APIs, and must never claim checkout, payment, fulfillment, persistence or production success.
