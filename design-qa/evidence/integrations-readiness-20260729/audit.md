# 系统与集成真实化设计审查

## 审查范围

- 页面：正式管理后台 `/admin/integrations`
- 用户目标：确认当前本地平台真正连通了哪些内部依赖、哪些能力只是仓库或 AWS 模板定义、哪些外部服务和后台任务尚未开发
- 证据：本轮真实浏览器截图 `01-current-preview-viewport.png` 至 `06-before-after-comparison.png`

## 步骤 01：当前系统与集成设计预览

- 健康状态：视觉结构稳定，但运行真实性不合格
- 优点：服务卡片和后台任务列表的层级清晰，页面只有一个主标题，状态标签容易扫描。
- UX 风险：页面宣称“数据库 99.99%”“对象存储正常”“邮件 2 个通知等待重试”“汇率每 30 分钟同步”，但仓库没有对应可用率、对象存储、邮件投递或外部汇率同步证据。
- 逻辑风险：四条后台任务使用虚构追踪编号与时间，并把汇率更新、库存释放和每日备份显示为已完成；项目没有调度器、队列、任务事件存储或这些自动任务的执行代码。
- 信任风险：“健康检查”只打开设计工作流，不查询 API、数据库、Valkey 或外部服务；主按钮形态会让管理员误以为检查已经发生。
- 数据边界：当前 `GET /v1/health` 只真实探测 API 与 MySQL；本地 Valkey 虽由 Compose 配置且登录会话使用它，但健康接口不检查 Valkey。Telegram 服务端明确未连接；媒体使用本地 `/assets/`；币种与汇率是 MySQL 管理值，不是外部提供商同步。
- 云边界：CDK 定义 ECS、RDS、Valkey、ALB、WAF、CloudWatch 与日志桶，但 AWS 尚未部署。日志桶不是媒体对象存储，模板定义也不是运行集成。
- 无障碍限制：截图可以确认层级、对齐和颜色，但不能单独证明完整键盘顺序、焦点样式、屏幕阅读器输出或 200% 缩放。
- 建议：删除虚构健康、重试、定时同步、追踪编号和成功任务；改为只读集成就绪中心，真实读取 API/MySQL 健康、获权时读取币种和 Telegram 配置，并把 Valkey、媒体、外部提供商、后台任务与 AWS 分成明确状态。

- 健康状态：通过，未发现 UI 重叠、页面级横向滚动、信息逻辑冲突或虚构成功。
- 信息真实性：运行探测、仓库定义、权限受限、未连接、未实现和未部署使用不同状态，不再用“降级”混合能力缺失。

## 步骤 06：Valkey 运行健康探测升级

- 健康状态：通过
- 运行证据：真实 `GET /v1/health` 返回 API `healthy`、MySQL `connected`、Valkey `connected`、MySQL/Valkey 本次非负整数耗时与时间戳。刷新页面后检查时间发生变化，证明页面重新读取真实 GET；该结果只代表本次请求，不代表可用率、容量或 SLA。
- 状态修正：摘要从两项变为三项，Valkey 从 `NOT_QUERIED` 升级为 `RUNTIME_VERIFIED`，对应未开发门禁删除，上线门禁从八项变为七项；Telegram、外部服务、后台任务和 AWS 的限制状态保持不变。
- 连接边界：健康控制器复用 `SessionService` 现有 Valkey 客户端执行有时限 `PING`，不创建第二条连接，也不读取会话、键值、地址或凭据。
- 桌面证据：`07-valkey-runtime-desktop.png`；1280 × 720 下文档 `scrollWidth === clientWidth === 1265`、一个 H1、可见按钮最小 44 × 44px，未发现卡片、文字、状态或操作重叠。
- 移动证据：`08-valkey-runtime-mobile-390.png` 与 `09-valkey-runtime-mobile-320.png`；390px/320px 下文档宽度分别为 375/305 且无页面级横向溢出，1420px 证据表只在 349px 内部容器横向滚动，可见按钮最小 44 × 44px。
- 英文修复：首次 320px 英文复核发现页面标题与语言切换重叠；已让标题容器可伸缩、语言切换固定宽度并允许极窄屏标题自然换行。`10-valkey-runtime-english-320.png` 显示修复后两个区域重叠面积为 0，320px 与 390px 英文均无页面级横向溢出。
- 控制台：最终干净页面 warning 0、error 0。
- QA 清理：一次性 `catalog.read` + `settings.read` 管理员、角色、权限关联和相关审计记录已删除，复核用户、角色和审计计数均为 0；临时凭据文件与验收脚本已删除，浏览器已退出并关闭标签。
