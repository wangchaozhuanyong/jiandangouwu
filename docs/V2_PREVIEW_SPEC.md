# CloudBridge V2 阶段一界面预览规范

## 1. 目的

阶段一用于在不改变生产业务的前提下，评审 CloudBridge V2 的信息架构、页面层级、视觉密度、响应式规则和双语文案。它不是正式功能开发，不增加生产路由、API、D1 表或可保存设置。

本规范只描述界面预览。正式数据和工程改造见 [V2 阶段二以后重构计划](V2_REFACTOR_PLAN.md)。

## 2. 真实性边界

| 层级 | 可以声称 | 不可以声称 |
| --- | --- | --- |
| 现有真实 | 现有商品、分类、Hero、币种、联系方式、单商品人工订单和后台运维能力已有正式代码与数据模型 | 当前未提交改动已经部署；外部服务仅因存在代码就已经可用 |
| 阶段一模拟预览 | V2 页面结构和交互方向可评审；模拟数据不会写入服务器 | 新导航、专题、Hero 开关、Skill 数据或业务流程已经上线 |
| 阶段二以后 | 完成正式契约、迁移、API、权限、测试和部署后，可按证据逐项声明 | 未经生产匿名复核就声明正式可用 |

阶段一预览必须遵守以下规则：

- 每个预览页面持续显示 `界面设计预览 / Interface design preview`，并写明“模拟或只读数据，服务器数据未更改”。
- 预览标识不可只放在帮助弹层、悬浮提示或页面底部。
- 不调用任何生产写接口，不创建订单、订阅、安装任务、付款、退款、发货或查询 Token。
- 前台预览只允许读取现有 `GET /v1/storefront/config`，用于真实币种、客服状态和 `transitServiceUrl`；读取失败时回退到带 DEMO 标识的类型化数据和诚实不可用状态。
- 前台不得读取商品、分类、订单或后台接口；后台预览不得产生任何 `/v1` 请求，所有编辑状态只保存在当前 React 内存。
- 不显示伪造的保存成功、订阅成功、支付成功、安装成功、发送成功或外部回执。
- 如复用真实只读商品数据，必须仍把页面和展示分配标记为预览；真实商品数据不等于新专题已经正式存在。

## 3. 预览入口与导航

阶段一与正式客户端隔离，使用以下本地开发预览地址；它们不是当前生产路由：

| 导航 | 中文 | English | 阶段一预览地址 | 阶段二候选正式地址 |
| --- | --- | --- | --- | --- |
| 1 | 首页 | Home | `/preview/v2/{locale}` | `/:locale` |
| 2 | 中转站订阅 | Transit subscriptions | `/preview/v2/{locale}/transit-subscriptions` | `/:locale/transit-subscriptions` |
| 3 | AI 软件代充 | AI software recharge | `/preview/v2/{locale}/ai-recharge` | `/:locale/ai-recharge` |
| 4 | Skill 推荐 | Skill recommendations | `/preview/v2/{locale}/skills` | `/:locale/skills` |
| 5 | 订单查询（独立服务入口） | Order lookup (separate service entry) | `/preview/v2/{locale}/orders/lookup` | `/:locale/orders/lookup` |
| 6 | 购物车（移动端独立页） | Cart (dedicated mobile page) | `/preview/v2/{locale}/cart` | 待正式多商品订单另行授权 |

其中 `{locale}` 当前只允许 `zh` 或 `en`，例如中文首页预览为 `/preview/v2/zh`。后台预览继续使用 `/admin/__preview/v2/...`，不得把 locale 放到 `/preview/v2` 之前，也不得把前台预览挂入正式 `/:locale` 路由树。

补充预览地址：

- `/preview/v2/{locale}/skills/[slug]`
- `/preview/v2/{locale}/products/[slug]`
- `/preview/v2/{locale}/cart`
- `/preview/v2/{locale}/policies/terms`
- `/preview/v2/{locale}/policies/privacy`
- `/admin/__preview/v2/products`
- `/admin/__preview/v2/categories`
- `/admin/__preview/v2/banners`
- `/admin/__preview/v2/skills`
- `/admin/__preview/v2/settings`

这些地址只在开发环境开放。生产环境必须返回 404 或不加载对应预览代码；后台四页还必须先通过真实管理会话，不能为了查看样板绕过身份保护。

预览导航要求：

- 768px 及以上保留顶部网站主导航：Logo、首页、Skill 推荐、订单查询、主题/语言/客服和购物车属于网站层级；中转站订阅与 AI 软件代充归入统一商品目录的分类/展示面，不与网站主导航重复。
- 760px 及以下保留透明背景 Logo、主题、语言与联系客服的紧凑页头；页头占据正常布局位置并固定在视口顶部，不随页面内容离开。不显示右上角购物车；底部固定四项主导航：`首页 / Home`、`Skill 推荐 / Skill recommendations`、`购物车 / Cart`、`订单查询 / Order lookup`。购物车入口直接进入独立页面，不打开移动弹层。
- 商品目录严格使用两级分类：顶部纯文字一级分类横栏、左侧纯文字二级分类栏、右侧商品结果。`全部商品 / All products` 是前台虚拟入口，不进入后台分类数据；商品只能归属二级分类。
- 移动二级分类使用左侧 72–76px 纯文字栏，不显示分类图标；中文四字标签完整显示。分类外框按实际分类数量收口，仅当分类超出可用高度时独立滚动，不能拉伸到商品列表底部。商品在右侧以左图右文横卡排列，右侧全部文字和操作高度不得超过左侧商品图。
- 当前正式页头不在阶段一被替换。只有阶段二路由、数据和发布门禁完成后，才允许迁移正式导航。
- 当前首页右下角外部“中转站服务”入口继续是外部动作，以带完整 `中转站 / Transit` 文案的 56px 环桥圆章显示：深海军蓝玻璃内芯、细青铜双环、青色拓扑图标和右上信号点；禁止再覆盖成长方形或长胶囊。它不能被当作“中转站订阅”专题页，也不能用预览页面假装完成订阅。

## 4. V2 首页

### 4.1 页面顺序

1. 顶部网站主导航与持续可见的预览说明。
2. 可选的横向图片 Hero。
3. 商品目录：桌面/平板在搜索栏下方展示一级分类横栏，在左侧展示二级分类，商品留在右侧；网站主导航继续位于顶部；紧凑移动端为顶部一级分类、左侧纯文字二级分类与右侧横向商品列表。

首页不再追加频道卡、四项保障、人工服务流程、FAQ、客服推广或页脚。购物车页同样移除页脚以保持任务聚焦；其他专题、Skill、查询与政策预览页继续保留紧凑页脚。页脚保留品牌、四项导航和法律说明三层语义，但不得使用大面积空白或松散 Logo 锁定。

### 4.2 Hero 两种状态

**显示状态**：

- 使用完整宽度的深色图片锚点，保留克制的圆点分页、定时轮播和滑动/拖动。
- 不显示页码分数、进度线或上一张/下一张箭头胶囊。
- CTA 在阶段一只允许跳转到预览内的只读内容；如明确跳往现有真实商品详情，必须标注“离开预览”，且不能把现有单商品人工下单描述成专题订阅、代充或 Skill 能力。

**关闭状态**：

- Hero 组件完全不渲染，不能出现骨架、空白占位、残留间距或假错误状态。
- 商品目录直接承接预览状态栏后的页面节奏。
- 状态来自隔离的预览 fixture 或测试注入，不显示假后台保存结果，也不新增生产设置字段。

### 4.3 商品目录

- 分类状态使用 `primary`、`secondary` 与 `q` URL 参数。切换一级分类必须重置二级分类；非法或已不存在的分类值回退到“全部”，不能生成空白页面。“全部商品”下左栏只展示当前展示面确实有商品的二级分类。
- 商品搜索与币种位于同一行，搜索框始终更宽；移动币种控件只显示 CloudBridge 币种 Token 与箭头。一级分类横栏位于其下。文档先滚动到整组目录控件；控件到位后固定在紧凑页头正下方，左侧二级分类与右侧商品结果分别滚动，不能让整个目录继续作为一个长页面滚动。
- 分类名称使用完整中英文，不截断，不使用 DOM 序号推导分隔线。
- 商品排序以只读数据或明确 fixture 的顺序为准，不根据视觉稿偷偷重排生产商品。
- 不显示匹配结果数量；保留清晰的无结果状态和重置操作。
- 商品卡片继续保持图片、名称、完整价格、库存和加入购物车入口的层级；除购物车按钮外，点击卡片任意区域进入商品详情，不显示额外的左箭头、右箭头或“查看详情”按钮。购物车只接收不同 DEMO 商品，不提供数量控件或分类 kicker。
- 购物车仅保存在当前 React 内存中。桌面从右侧展开，移动端进入 `/preview/v2/{locale}/cart` 独立页面；表单只采集一个联系渠道和联系值。独立页面的合计与“提交人工订单”固定在视口底部，移动端位于四项导航上方，并预留遮挡安全区；页面下方显示“您可能喜欢”模拟商品纵向列表，每行只展示一个横向商品卡，不使用横向货架或左右滑动。点击提交只完成本地校验，并明确提示未创建订单、未保存服务器数据。
- 商品详情使用与商品卡相同的图片来源和 1:1 图片框，不能出现目录横图与详情竖图的型号不一致。

## 5. 专题页预览

### 5.1 中转站订阅

预览内容可以包括：专题说明、适用场景、分类筛选、方案或商品卡片、交付边界和常见问题。所有“订阅”动作必须禁用或明确标记为预览，不得创建周期订单、自动续费或外部服务记录。

当前外部中转站 URL 仅用于已有外部入口。阶段一不得把该 URL 伪装成站内订阅 API，也不得复用联系方式成功状态冒充订阅成功。

### 5.2 AI 软件代充

预览内容可以包括：服务说明、软件分类、商品陈列、人工处理时间和风险提示。商品展示可复用当前商品卡片视觉，但展示分配仅是模拟关系；不能暗示已经新增真实专题字段。

“代充”仍走未来可能的人工联系边界。阶段一不得出现账号密码采集、支付表单、自动充值、自动履约或完成回执。

### 5.3 Skill 推荐

Skill 推荐是内容推荐，不是商品分类。预览卡片至少包括：

- Skill 名称和双语摘要。
- 独立内容分类。
- 来源或维护者说明。
- GitHub 外链及明确的外部跳转标识。
- “推荐”不等于安全认证、官方背书、已安装或可购买的真实性说明。

GitHub 链接只允许安全的 `https://github.com/...` 地址，使用新标签页时必须采用 `noopener noreferrer`。无效或缺失链接显示不可用状态，不生成猜测地址，不提供自动安装。

Skill 列表只使用一个内容分类层级，不复用商品的一、二级分类：

- 横向 Hero 保持在列表上方；其下是全宽搜索框，再下方使用左侧纯文字分类栏与右侧 Skill 结果区。
- `全部 Skill / All skills` 是前台虚拟入口；分类栏只渲染当前确实包含可见 Skill 的分类，不展示或禁用空分类。
- 搜索与分类状态使用 `q` 和 `filter`；非法分类值必须回退并清理为“全部 Skill”，切换分类保留搜索词，不显示匹配结果数量。
- 移动端搜索框与下方带边框的分类/结果目录保持约 16px 明确间距，避免两层边框紧贴形成错误的组合控件观感。
- 1440px 使用 160–176px 左栏与三列紧凑卡；1024px、768px 使用 136–152px 左栏与两列卡；390px 使用 76px、320px 使用 72px 左栏，右侧均为 116px 单列横卡。
- 移动端搜索到达 68px 紧凑页头后吸附，分类栏与结果区分别滚动；分类栏按实际行数收口，仅在内容超过可用高度时滚动。
- 卡片固定显示类型、来源、名称、两行摘要、兼容环境、核验日期与独立 GitHub 外链。除 44px GitHub 操作外，整卡进入详情；不重复显示“阅读详情”按钮。
- 安装前检查改为结果区底部的安静提示条；详情页不增加分类栏，相关推荐复用紧凑卡片。

## 6. 响应式验收矩阵

| 验收宽度 | 分类导航 | 商品列数 | 关键要求 |
| --- | --- | --- | --- |
| 1440px | 顶部一级分类 + 160–176px 二级栏 | 5 列 | 商品区占主视觉，卡片等高节奏稳定 |
| 1024px | 顶部一级分类 + 紧凑二级栏 | 2 列 | 不压缩价格和 44px 操作目标 |
| 768px | 顶部一级分类 + 窄二级栏 | 2 列 | 页面无横向溢出，分类和商品区都可收缩 |
| 390px | 顶部一级分类 + 76px 左侧二级栏 | 右侧单列横卡 | 四字分类完整，分类外框按内容收口，右侧内容高度不超过商品图 |
| 320px | 72px 左侧纯文字栏 | 右侧单列横卡 | 保留完整品牌名、价格和 44px 操作目标 |

实现断点时，以这五个验收视口的确定结果为准。推荐规则为：`>=1280px` 五列，`761px–1279px` 两列，`<=760px` 左栏加横向商品单列；如工程实现采用其他断点，必须仍满足表中结果并由测试锁定。

## 7. 商品详情与全局状态

- 商品详情不显示全站页头和页脚，图片顶部保留 44px 返回与分享入口；移动端滚动后显示安全区适配的紧凑标题栏。
- 底部操作栏始终固定在视口底部，页面保留足够底部空间；操作只触发本地表单校验。
- 表单最后只能显示“界面校验完成，未创建订单，也未保存服务器数据”，不得生成订单号、绿色业务成功状态或外部回执。
- 全局覆盖加载、空、错误、离线、图片失败、无客服、外链不可用和 404 状态；错误状态不得用 0 条记录冒充未知结果。

## 8. 后台四页

- 商品：为同一 DEMO 商品多选首页、中转站订阅、AI 软件代充展示位置，只预览本地分发结果。
- 广告：严格使用 `HOME`、`TRANSIT_SUBSCRIPTIONS`、`AI_RECHARGE` 三个 placement，提供内容与桌面/移动端效果预览。
- 商品分类：桌面双栏管理一级与二级分类，移动端使用一级折叠列表；新增和编辑明确级别，二级必须选择一级且不提供三级。商品编辑按“先一级、后二级”级联选择，最终只保存二级分类。
- Skill：内容与分类双标签，覆盖双语、类型、来源级别、兼容环境、许可证和 HTTPS 来源校验。
- 设置：只展示三个广告开关；切换、权限不足和版本冲突都只是本地界面状态。
- 四页持续显示服务器写入关闭的真实性说明，不显示保存、发布、上传、发送或集成成功。

## 9. DEMO 订单查询

- 路由固定为 `/preview/v2/{locale}/orders/lookup`，只使用 `DEMO-*` Fixture，不读取真实订单或调用 `/v1/orders`。
- 页面顶部只使用紧凑标题与说明，不设置 Hero、插画或大面积图片区域。
- 页面不再单独显示“返回服务目录”，退出路径统一使用顶部主导航或移动底部导航，避免重复导航。
- 查询工作台顶部固定使用三个等宽标签：`本机订单 / On this device`、`联系方式 / Purchase contact`、`订单号 / Order number`。切换只改变 React 内存状态，不写 URL 查询值。
- 本机订单只展示 React 内存中的安全摘要，支持清除与恢复 DEMO 记录；不得把订单写入 `localStorage`、跨设备同步或读取服务器订单。
- 联系方式查询先填写渠道与下单联系方式，再进入 DEMO 所有权验证步骤；通过固定 DEMO 验证码后才显示结果。未知联系方式和错误验证码使用相同说明，联系方式本身不得直接枚举订单。
- 订单号查询只接受提交成功时提示的完整高熵 DEMO 订单号；只展示精简结果，不把订单号写入 URL、浏览历史或服务器日志。
- 三种方式统一覆盖空输入校验、固定加载、统一无匹配、尝试过多、服务不可用和 DEMO 精简结果。加载状态不得通过计时器自动变成成功。
- 精简结果只展示商品、金额、稳定状态、渠道、脱敏联系方式与创建/更新时间，不展示完整联系方式、Telegram、负责人、内部备注或历史时间线。
- 商品详情表单校验完成后，可以展示“正式订单后可保存订单号”和预览查询入口，但不得生成假订单号或业务成功回执。

## 10. 视觉与交互约束

- 深色“夜航画廊”保持默认；浅色“瓷白双港”是正式组件基线，两套主题覆盖全部预览页面和状态。
- 维持冷瓷白、深海军蓝、克制青色桥线、编辑式大字和安静动效，不引入高饱和电商促销风格。
- 货币使用 CloudBridge 货币标识，不使用 emoji 国旗或通用金币图标。
- 所有可见文案提供完整 `{ zh, en }`；中文和英文必须分别检查溢出，不允许仅缩小字号掩盖布局问题。
- 交互目标至少 44 × 44px，键盘焦点清晰，弹层支持 Escape、焦点锁定与恢复。
- 尊重 `prefers-reduced-motion`；动画不能承担唯一的信息传递。
- 加载、错误、空状态、图片失败、外链不可用和无客服渠道状态都必须诚实显示。

## 11. 阶段一明确禁止

- 生产购物车、数量选择器、持久化购物篮和真实多商品结算；阶段一仅允许不同 DEMO 商品的内存购物车与非提交式人工订单表单。
- 新增或变更订单模型、库存扣减方式和 `order_items`。
- 在线支付、Webhook、自动退款、资金对账和支付成功画面。
- 客户登录、会员、积分、优惠券和跨设备同步。
- 自动发货、自动订阅、自动续费、自动充值和自动安装 Skill。
- 真实公开订单查询、真实联系方式匹配、随机查询 Token，以及任何订单数据读取或写入；仅允许本规范中的三模式 DEMO 界面。预览中的联系方式或订单号单入口不代表正式生产接口已经获得授权。
- 新增生产 API、D1 迁移、密钥、第三方集成或部署配置。
