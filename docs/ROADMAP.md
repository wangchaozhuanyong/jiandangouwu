# CloudBridge 路线图与开放问题

## 使用方式

每个开发任务开始前记录目标、当前状态、范围、非目标、依赖、风险、验收和所需检查。一次只推进一个清晰任务；未解决的高风险决定留在开放问题中，不在代码里擅自选定。

## 当前阶段

### 已完成设计任务：管理后台数据表全局单行规范

- 目标：消除订单号下方时间、金额下方币种、联系方式下方账号等多行记录表达，统一后台数据扫描方式。
- 完成范围：根目录遗留 Vite 设计原型中的订单、商品、分类、翻译、币种、团队、审计、支付、安全与 Telegram 记录表。
- 设计结果：一个字段一列、一条记录一行；桌面端优先同屏，390px 移动端使用表格内部横向滑动，不使用多行卡片。
- 安全边界：联系方式继续脱敏；本轮不连接数据库、服务器、支付或 Telegram。
- 验收：26 项遗留原型测试、规则检查和 Vite 生产构建通过；桌面端、390px、中英文与控制台复验通过。
- 证据：见根目录 `design-qa.md` 的“2026-07-28 管理后台数据表全局单行设计”。

### 当前实施任务：TypeScript 全栈重建与 AWS staging 准备

- 目标：把 CloudBridge 拆为 Next.js 客户端、Vite 管理后台、NestJS API、Prisma MySQL 与 AWS CDK。
- 当前能力状态：本地目录、搜索、分类、币种、人工订单、密码登录、可选 TOTP 双重验证、服务端会话、RBAC 与审计已实现；AWS 只完成模板，尚未创建资源。
- 费用门禁：当前高可用模板按低流量估算约 `$420–$460/月`，以 [AWS staging 规划](AWS_STAGING.md) 为准，部署前重新核价并获得明确授权。
- 范围：本地全栈、迁移与种子、前后台真实 API、容器、AWS 新加坡高可用 staging 模板、类型/构建/接口/浏览器检查。
- 非目标：在线支付、Telegram 真实发送、生产部署、生产数据迁移。
- 验收标准：所有工作区类型和构建通过，本地三服务可访问，数据库写入和幂等检查通过，CDK synth 通过，桌面/390px 及中英文视觉回归通过。
- 自动检查：`npm run check` 与 `npm run synth --workspace @cloudbridge/infra -- --no-lookups`。
- 浏览器检查：客户端首页/详情/订单、后台登录/分类/商品/订单/币种/安全，桌面与 390px。
- 上线阻断：`npm audit --omit=dev` 当前仍有 6 项上游 high 公告；不阻断本地设计和功能验收，但在 AWS staging 创建前必须重新审计并处理或获得逐项风险批准。

### 阶段 0：规则基线

- 建立项目级开发、架构、数据、安全、交互和测试规则。
- 增加不依赖第三方包的规则检查与统一检查命令。
- 保留当前前端原型，不拆分应用、不迁移 JSX、不创建后端。

完成标准：规则相互一致、现有测试与构建通过，开发者可以直接确定技术栈、能力状态、确认规则、数据安全边界和交付要求。

## 后续候选阶段

### 阶段 1：AWS staging 创建与联调

- 确认域名、ACM 证书、AWS 账户、费用和受控首位管理员创建流程后执行 CDK diff/deploy。
- 先运行一次性迁移任务，再启动服务并核对 RDS、Valkey、WAF、告警和日志。
- 完成真实验证器的 TOTP 开启、登录和关闭验收。

### 阶段 2：真实业务集成

- 按优先级接入订单、Telegram 管理群通知、客服通知、汇率、权限和审计。
- 每个集成独立处理未连接、超时、重试、幂等和部分失败。
- 没有真实外部证据时继续标记为未接通或模拟。

### 阶段 3：生产准备

- 确定托管、域名、数据库、备份、监控、告警和回滚策略。
- 完成测试环境端到端验收、安全检查和恢复演练后再申请生产发布。

- 联系方式、订单和审计数据的保留期限及合规要求。
- 媒体是否迁移到对象存储、是否需要通知队列及其真实容量依据。
- 监控、告警、备份恢复目标和生产发布责任人。
- Next.js、Nest Swagger 与 AWS CDK 稳定版上游依赖安全公告的修复版本、兼容性验证与风险责任人。

### 遗留原型客户端分类导航胶囊选中态

- 目标：按已选 Product Design 方案 1，用轻量胶囊选中态替代底部横线，并让长分类导航在点击后自动滚动到可视区域中部。
- 当前能力状态：根目录遗留 Vite 客户端已有单选分类筛选与横向滚动，但选中态依赖底部横线，分类较多时缺少溢出方向提示。
- 范围：根目录 `src/` 分类导航交互与样式、横向溢出状态函数及专项测试。
- 非目标：主平台 `apps/storefront`、分类数据、API、数据库、管理后台、部署和生产配置。
- 风险：窄屏边缘渐隐遮挡文字、平滑滚动影响减少动态效果用户、分类内容变化后溢出状态不同步。
- 验收标准：选中项为青色低对比胶囊且无底部横线；只在对应方向仍可滚动时显示边缘渐隐；点击分类后自动居中；320px、390px、桌面端及中英文无横向页面溢出；键盘焦点清晰。
- 自动检查：`npm run test:ux`、`npm run build` 与 `npm run check`。
- 浏览器检查：1440 × 1024、390 × 844、320 × 844，中英文、首项/中间项/末项切换、减少动态效果和控制台。
- 当前记录：胶囊选中态、动态边缘渐隐、点击自动居中、减少动态效果兼容及键盘焦点均已实现；`test:ux` 7/7、遗留 Vite 构建和完整 `npm run check` 通过。当前会话未暴露 Browser 插件控制能力，真实渲染截图、交互和同屏视觉比较仍待复验，`design-qa.md` 保持 `final result: blocked`。
