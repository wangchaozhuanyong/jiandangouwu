### 待确认任务：库存预留到期返库与后台任务运行时

- 目标：为真实有限库存订单实现可重启、幂等、可审计的预留到期返库，避免 30 分钟库存保留到期后永久少库存，并让人工取消与自动到期使用同一套库存释放规则。
- 已确认现状：公开下单会在 Serializable 事务中原子扣减有限库存并保存 `reservedUntil`；人工取消只更新订单状态，没有返库；当前没有调度器、队列、Worker 或返库任务。
- 数据缺口：`Order` 只保存下单时的 `productVersion`，没有保存该订单是否实际扣过有限库存、库存是否已经返还或返还时间。商品可在下单后切换 `FINITE` / `UNLIMITED`，因此根据商品当前模式推断返库会产生多加或漏加库存的风险。
- 推荐业务规则：新增订单级库存预留标记与释放时间；只有实际扣减过有限库存且尚未释放的订单可以返库。`MANUAL_PENDING`、`CONTACTED`、`AWAITING_PAYMENT` 超过 `reservedUntil` 后自动转为 `CANCELLED` 并返还一件；`PAYMENT_PROCESSING`、`PAID` 及后续状态不自动取消。人工把可取消的未支付订单转为 `CANCELLED` 时同样只返还一次。
- 推荐实现：新增经过审查的 Prisma migration；下单扣库存、订单预留标记和初始历史保持同一 Serializable 事务；自动任务按小批量扫描候选订单，每张订单通过条件更新与事务实现多实例幂等，并在同一事务写订单历史和 `order.reservation.expire` 审计。多个 API 实例允许重复扫描，但只有一个条件更新成功，不依赖进程内锁宣称分布式安全。
- 迁移边界：历史订单无法安全推断是否曾扣过有限库存，迁移默认将其标记为“不由新任务自动返库”，避免错误增加库存；只有新版本创建且真实扣减成功的订单进入自动返库。当前本地数据库只有 1 条 `REFUND_PENDING` + `UNLIMITED` 历史订单，不在推荐自动取消范围内。
- 非目标：不新增第三方队列或调度依赖、不接支付、邮件、Telegram、外部汇率或 AWS；不自动处理 `PAYMENT_PROCESSING`、已付款、履约、售后或争议订单；不把进程内最后运行时间伪装成持久化任务历史。
- 决策门禁：本任务需要用户确认数据库结构与上述自动取消范围。确认前不创建 migration、不写自动返库、不改真实订单状态。
- 预定验收：有限库存只扣一次、只返一次；无限库存不变；人工取消与自动到期共享规则；并发任务和管理员状态更新最多一个成功；失败整笔回滚；重启后能继续扫描；历史和审计与状态/库存同事务；真实本地 QA 订单完成扣减、到期、取消、返库和清理闭环。

### 遗留原型客户端分类导航胶囊选中态

- 目标：按已选 Product Design 方案 1，用轻量胶囊选中态替代底部横线，并让长分类导航在点击后自动滚动到可视区域中部。
- 当前能力状态：根目录遗留 Vite 客户端已有单选分类筛选与横向滚动，但选中态依赖底部横线，分类较多时缺少溢出方向提示。
- 范围：根目录 `src/` 分类导航交互与样式、横向溢出状态函数及专项测试。
- 非目标：主平台 `apps/storefront`、分类数据、API、数据库、管理后台、部署和生产配置。
- 风险：窄屏边缘渐隐遮挡文字、平滑滚动影响减少动态效果用户、分类内容变化后溢出状态不同步。
- 验收标准：选中项为青色低对比胶囊且无底部横线；只在对应方向仍可滚动时显示边缘渐隐；点击分类后自动居中；320px、390px、桌面端及中英文无横向页面溢出；键盘焦点清晰。
- 自动检查：`npm run test:ux`、`npm run build` 与 `npm run check`。
- 浏览器检查：1440 × 1024、390 × 844、320 × 844，中英文、首项/中间项/末项切换、减少动态效果和控制台。
- 当前记录：胶囊选中态、动态边缘渐隐、点击自动居中、减少动态效果兼容及键盘焦点均已实现；`test:ux` 7/7、遗留 Vite 构建和完整 `npm run check` 通过。当前会话未暴露 Browser 插件控制能力，真实渲染截图、交互和同屏视觉比较仍待复验，`design-qa.md` 保持 `final result: blocked`。
