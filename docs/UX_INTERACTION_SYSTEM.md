# CloudBridge 全站体验与交互系统

本规范适用于根目录遗留设计原型、`apps/storefront` 正式客户端和 `apps/admin` 正式后台。遗留原型只作为交互基准；正式能力、数据与权限证据只能来自 `apps/` 主平台。

## 体验目标

- 用户操作后 100ms 内出现按下、选中或禁用反馈，快速请求不闪现 Spinner。
- 导航外壳、页头、后台侧栏和顶部栏在页面切换时保持稳定；内容进入使用 180ms、6px 的克制过渡，不使用阻塞式退场动画。
- 首次加载显示与最终结构一致的骨架；刷新、搜索、筛选和币种切换保留旧数据并使用 `aria-busy`。
- 超过 8 秒仍未返回时显示真实慢网络提示；离线、失败、空数据和重试分别表达。
- 订单、支付、安全、权限、汇率、价格与库存只能在服务端确认后显示成功。

## 状态模型

客户端和后台分别声明相同语义的本地类型，不把界面状态加入共享业务契约：

```ts
type AsyncViewState =
  | "idle"
  | "initial-loading"
  | "refreshing"
  | "ready"
  | "empty"
  | "offline"
  | "error";

type MutationState = "idle" | "submitting" | "success" | "error";
```

| 时间或状态 | 反馈 |
| --- | --- |
| 0–120ms | 立即显示按下、选中、禁用或当前导航状态 |
| 120–400ms | 局部进度条、按钮提交状态或轻量刷新提示 |
| 超过 400ms | 与最终内容同尺寸的结构骨架 |
| 超过 8 秒 | 慢网络说明与继续等待、重试或取消能力 |
| 页面进入 | 180ms opacity 与 6px 位移 |
| 抽屉 / 弹窗 | 220ms / 180ms |
| Toast | 160ms；错误持续到用户关闭或下一次结果 |

开启 `prefers-reduced-motion: reduce` 后取消位移、循环骨架和连续旋转，只保留近乎即时的状态变化。

## 客户端规则

- `[locale]/layout.tsx` 持续挂载 `SiteShell`；路由级 `loading.tsx` 和 `error.tsx` 只接管内容区域。
- 首屏在服务端并行读取配置、分类和商品；客户端后续搜索与筛选取消过期请求。
- 搜索与分类写入 URL；币种只保存到会话存储；联系账号和订单草稿只保存在根级内存状态。
- 商品卡片只在 hover/focus 时预取动态详情；返回列表恢复过滤条件与滚动位置。
- 一个订单草稿只生成一个幂等键，失败或响应丢失后的重试必须复用；收到服务端凭证后才清空草稿。
- 商品和轮播图预留稳定比例与尺寸，失败时显示可读占位；只有当前首屏轮播使用高优先级加载。
- 商品区不得显示可见结果数量；读屏状态可以播报结果数量。

## 后台规则

- 正式后台按 `/admin/:page` 懒加载，侧栏与顶部栏持续挂载。`ADMIN_PAGES` 中的当前路由均由真实或明确受限的专属模块承载，独立设计预览模块已删除；没有服务器能力的页面直接显示未开发、未连接、未部署或无权限，不得把交互演示作为保存成功或功能可用证据。
- 已认证后台使用视口级应用壳层：壳层固定为 `100dvh`，桌面侧栏和顶部栏保持稳定，`.admin-main` 是唯一纵向工作区滚动容器；侧栏导航可独立滚动且账户区始终留在视口内。移动端维持固定全高抽屉。后台内容不得退回文档级滚动，也不得在侧栏下方留下空白。
- 所有后台路由、面板、表单和网格/Flex 子项必须能在可用宽度内收缩，不得产生页面级横向溢出。需要额外宽度的表格或控件必须放入命名的内部滚动容器；不得通过缩小字号或裁掉必要内容掩盖边界错误。
- 页面、区块、弹窗和技术字段的稳定功能说明统一放在标题右侧的问号帮助入口中，并提供完整中英文文案。当前状态、校验错误、权限、前置条件、破坏性影响、能力真实性边界和保存结果必须直接显示，不得藏入帮助说明。
- 问号帮助入口支持点击、键盘和移动端触控，点击外部或按 Escape 关闭，键盘关闭后焦点返回触发按钮；触控目标至少 44 × 44px，窄屏浮层不得产生页面横向溢出。
- 页面查询使用 30 秒内存缓存；新页面首次进入使用骨架，返回页面优先显示缓存，过期后后台刷新。
- 写入成功后失效相关缓存；失败保留表单值并禁止重复提交。
- 弹窗支持初始焦点、Tab 焦点循环、Escape、背景关闭、关闭后焦点返回和页面滚动锁定。
- 所有结构化表格保持一条记录一行；移动端在表格内部横向滚动，可固定首尾关键列，不改成卡片、不隐藏关键列。
- 导航与行级操作触控目标至少 44px，主导航至少 48px。
- 成功和普通状态使用礼貌型播报；关键错误使用 `alert`；敏感操作继续要求服务端权限、重新认证与审计。

## 验收与证据

- 自动检查：`npm run test:ux`、`npm run test:admin-navigation`、`npm run test:platform`、`npm run typecheck:platform`、`npm run check`。
- 浏览器视口：1440 × 1024、390 × 844、320 × 844，中英文分别覆盖。
- 网络场景：冷缓存、热缓存、Slow 4G、离线、8 秒延迟、API 4xx/5xx、图片失败、过期搜索和订单响应丢失后重试。
- 没有 Browser 实际截图、焦点、控制台和网络证据时，`design-qa.md` 必须保持 `blocked`，不得以类型检查或构建通过代替视觉验收。
- Core Web Vitals 目标为真实用户第 75 百分位 LCP ≤ 2.5s、INP ≤ 200ms、CLS ≤ 0.1；只有实验室数据时必须明确标注。
