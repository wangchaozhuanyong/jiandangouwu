# CloudBridge 数据、接口与安全规则

## 当前边界

当前本地平台已有 NestJS API、Prisma schema、MySQL 数据库和 Valkey 服务端会话；根目录遗留原型的浏览器存储仍只是模拟数据，不能作为可信数据源。

数据库传输按环境分开控制：本地 Docker MySQL 8.4 通过 `DB_ALLOW_PUBLIC_KEY_RETRIEVAL=true` 支持 `caching_sha2_password`，仅用于本机网络；AWS/RDS 必须设置 `DB_TLS=true`，并保持公钥拉取关闭。不得通过降低 MySQL 用户认证插件来解决连接问题。

当前实现不等于生产发布：AWS 资源尚未创建，生产域名、备份恢复、告警接收人、支付与真实通知仍待实施和验收。

## 金额与币种

- 后端使用 Decimal 处理金额，禁止使用 `float`、`double` 或 JavaScript 二进制浮点完成结算计算。
- API 以十进制字符串传递金额，例如 `{ "amount": "89.00", "currency": "MYR" }`。
- 币种、精度、汇率来源和更新时间必须显式记录；显示格式不得反向成为计算输入。
- 价格、库存和汇率变更属于高风险操作，必须记录操作者、变更前后值、时间和原因。

## 状态与数据完整性

- 订单、付款、库存、通知、账号和集成状态使用稳定枚举码。
- 翻译文本只负责显示，不得决定样式、权限或状态流转。
- 状态转换必须由服务端校验合法性；客户端不能通过提交任意状态跳过流程。
- 创建订单、付款确认、通知发送等可重试写入必须设计幂等键，重复请求不能产生重复结果。
- 关联数据使用稳定 ID；改名、翻译或排序不得改变关系。

## API 约定

- 成功响应返回业务数据，可选返回分页或追踪元数据。
- 失败响应至少包含稳定错误码、适合用户理解的消息和请求追踪 ID；不得把内部堆栈直接返回前端。
- 列表在确有规模需求时支持分页、关键词搜索和受控排序；排序字段必须白名单校验。
- 所有输入在服务端验证类型、长度、格式和业务约束；客户端验证只用于体验。
- 写接口必须返回真实提交结果。排队任务返回任务 ID 和初始状态，不返回虚假的最终成功。

## 认证与权限

- 客户端保持无账户设计，不因此获得后台能力。
- 后台已独立认证，并在 API 层执行权限码授权；公开目录接口与 `/v1/admin/*` 权限边界分离。
- 后台主认证使用邮箱与经过 scrypt 派生存储的管理员密码。
- TOTP 默认为关闭状态；管理员可在安全中心开启或关闭。开启后，密码验证成功还必须完成 6 位动态码验证。
- 会话由服务端管理，只通过 `HttpOnly`、`Secure`、`SameSite` Cookie 关联；禁止将管理员 Token 写入 `localStorage` 或 `sessionStorage`。
- 无权限时界面隐藏或禁用操作，API 同时返回明确的权限错误。
- 登录、敏感查看、导出、权限修改、支付配置、退款和恢复操作必须支持会话控制、限速、重新认证、二次确认与审计。
- 当前本地密码登录、可选 TOTP、会话、RBAC 代码和类型检查是实现证据；仍需验证器真机、渗透测试和 AWS staging 联调才能形成发布证据。

## 敏感信息

- 联系方式默认脱敏；查看、复制和导出完整值属于敏感操作。
- 生产环境的敏感字段应加密存储，密钥与数据分离管理。
- 日志、错误、分析事件和通知内容不得包含密钥、Token、密码或不必要的完整个人信息。
- 测试数据使用明显的虚构值，不在仓库中保存真实客户信息。

## 支付与 Webhook

- 客户银行卡和钱包凭据只在合规第三方托管支付页收集；本站不提供卡号、有效期或 CVV 输入框。
- 支付密钥只显示是否配置、使用范围和末尾标识，不得返回或记录完整值。
- 正式启用支付需要重新认证、影响预览、二次确认与不可变审计记录。
- Webhook 必须验证签名、时间窗口和事件类型，按提供商事件 ID 幂等处理；重复事件返回成功但不重复执行业务。
- 事件延迟、签名失败、处理失败、重试耗尽和对账差异是独立告警状态。
- 退款、部分退款、拒付和争议采用独立状态机；审批人与申请人应分离。

## 数据治理与恢复

- 数据按公开、内部、个人和机密分级，为每类记录收集目的、访问范围、保留期、删除或匿名化规则。
- 完整联系方式默认脱敏；揭示时记录人员、时间、订单、设备和原因。
- 访问、更正、导出和删除请求进入有时限、有负责人、有结果证据的隐私请求流程。
- RDS 启用加密、自动备份和时间点恢复；设计目标为 RPO 不高于 5 分钟、核心服务 RTO 不高于 60 分钟。
- 每次恢复演练在隔离环境执行，验证订单、权限和对象完整性后销毁环境并归档证据。
- 数据库密码、支付密钥、Webhook 密钥和第三方 Token 只存于 Secrets Manager/KMS，应用按最小权限读取并定期轮换。

## 审计与外部操作

- 创建、更新、删除、启停、价格/库存调整、权限变更和敏感信息操作记录审计事件。
- 审计至少包含操作者、动作码、目标 ID、结果、时间、请求追踪 ID；高风险变更记录前后差异。
- 通知、支付、汇率和第三方集成必须保存真实外部结果或失败原因。
- 未连接、超时、排队、部分成功和失败是独立状态，不得合并显示为成功。

## Telegram 订单通知

- Telegram Bot Token 只能由未来服务端从 Secrets Manager/KMS 读取，不得放入前端、`VITE_` 环境变量、浏览器存储、日志或消息模板。
- 订单通知默认发送到内部管理群，机器人只申请发送消息所需的最小权限，不读取群历史，也不处理客户私聊。
- 推送内容使用字段白名单：订单号、商品、金额、币种、订单状态、创建时间、联系渠道、脱敏联系方式和后台订单链接。
- 完整联系方式、内部备注、付款凭据、登录信息、密钥和未脱敏个人信息禁止进入 Telegram 消息。
- 每个订单事件使用稳定事件 ID 和幂等键；Telegram 超时、限流、失败、排队和重试耗尽必须保留为独立状态。
- 发送记录至少保存目标群末尾标识、事件 ID、订单 ID、尝试次数、外部结果、追踪 ID 和时间，不保存 Bot Token 或不必要的个人数据。
- 启用、停用、变更目标群和轮换机器人凭据需要重新认证、影响预览、二次确认与审计。
