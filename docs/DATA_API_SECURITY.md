# CloudBridge 数据、接口与安全规则

## 当前边界

当前本地平台已有 NestJS API、Prisma schema、MySQL 数据库和 Valkey 服务端会话；根目录遗留原型的浏览器存储仍只是模拟数据，不能作为可信数据源。

数据库传输按环境分开控制：本地 Docker MySQL 8.4 通过 `DB_ALLOW_PUBLIC_KEY_RETRIEVAL=true` 支持 `caching_sha2_password`，仅用于本机网络；AWS/RDS 必须设置 `DB_TLS=true`，并保持公钥拉取关闭。不得通过降低 MySQL 用户认证插件来解决连接问题。

当前实现不等于生产发布：AWS 资源尚未创建，生产域名、备份恢复、告警接收人、支付与真实通知仍待实施和验收。

## 金额与币种

- 后端使用 Decimal 处理金额，禁止使用 `float`、`double` 或 JavaScript 二进制浮点完成结算计算。
- API 以十进制字符串传递金额，例如 `{ "amount": "89.00", "currency": "MYR" }`。
- 币种、精度、汇率来源和更新时间必须显式记录；显示格式不得反向成为计算输入。
- 价格、库存和汇率变更属于高风险操作，必须记录操作者、变更前后值、时间和原因。

## 状态与数据完整性

- 订单、付款、库存、通知、账号和集成状态使用稳定枚举码。
- 翻译文本只负责显示，不得决定样式、权限或状态流转。
- 状态转换必须由服务端校验合法性；客户端不能通过提交任意状态跳过流程。
- 创建订单、付款确认、通知发送等可重试写入必须设计幂等键，重复请求不能产生重复结果。
- 同一订单幂等键只允许重放同一业务载荷；使用同一键提交不同商品、金额、币种、渠道、联系方式或政策版本必须返回冲突。
- 关联数据使用稳定 ID；改名、翻译或排序不得改变关系。

## API 约定

- 成功响应返回业务数据，可选返回分页或追踪元数据。
- 失败响应至少包含稳定错误码、适合用户理解的消息和请求追踪 ID；不得把内部堆栈直接返回前端。
- 列表在确有规模需求时支持分页、关键词搜索和受控排序；排序字段必须白名单校验。
- 所有输入在服务端验证类型、长度、格式和业务约束；客户端验证只用于体验。
- 写接口必须返回真实提交结果。排队任务返回任务 ID 和初始状态，不返回虚假的最终成功。

### 双语内容工作台

- `/admin/translations` 不拥有独立通用写接口。它只调用当前账号有权读取的商品、分类、首页轮播、客服渠道和站点设置接口，并在保存时回到所属模块。
- 商品和分类使用 `catalog.read/write`，首页轮播使用 `content.read/write`，客服渠道使用 `support.read/write`，站点设置使用 `settings.read/write`；聚合页面不得放宽、合并或绕过这些权限。
- 每次写入提交所属实体的完整必要字段和预期版本，继续执行原接口的服务端校验与 CAS；站点设置还保留最近认证、业务原因和审计要求。
- 中文和英文均按所属字段限制校验，空值或超长值失败关闭。界面不得用另一语言内容填补缺失值，也不得把前端完整度统计当作服务器提交证据。

### 媒体引用清单

- `/admin/media` 不拥有独立媒体接口。它按 `catalog.read` 逐页读取全部商品，并按 `content.read` 读取首页轮播；没有某项读取权限时不得请求或展示对应记录。
- 清单只聚合数据库中的 `imageKey` 引用。相同路径保留全部来源记录、稳定记录键、状态和更新时间，搜索和类型筛选只是前端派生状态。
- 仅 `/assets/` 下无路径穿越、无重复斜线且扩展名为 AVIF、GIF、JPEG、PNG 或 WebP 的路径可进入图片预览；外部 URL、SVG 和不安全路径不得被当作可加载本地图片。
- 浏览器加载成功和自然像素尺寸只代表当前本地请求结果，不代表文件字节已检查、资源已优化、对象存储已同步、CDN 可用或生产安全。
- 页面不得提供上传、替换、删除、未引用文件扫描或对象存储状态写入。商品或轮播通过原模块更新后，只能清除媒体页前端缓存，不能绕过原写权限和服务端校验。

### 安全审计信号

- `/admin/security-events` 读取现有 `GET /v1/admin/audit?page=1&pageSize=100`，继续要求 `audit.read`；没有独立安全事件写接口，也不扩大审计权限。
- 页面只从最近 100 条 MySQL `AuditEvent` 中投影登录、角色与权限、敏感联系方式查看、关键配置变更和所有 `DENIED` 记录。普通成功内容编辑不被虚构为安全事件。
- `high`、`medium`、`low` 只是固定的人工复核优先级：登录失败、任何 `DENIED` 或已纳入安全范围的 `FAILED` 为高优先级；敏感成功操作按固定类别进入中低优先级。它们不是攻击概率、自动阻止或外部威胁结论。
- 安全事件页面不得执行账号锁定、跨账号会话处置、权限修改、自动告警、事件结案或导出，也不得宣称已经接入 SIEM、威胁情报、关联检测或通知服务。当前账号的其他 Valkey 会话只能在安全中心由管理员手动撤销。

### 审计日志工作台

- `GET /v1/admin/audit` 继续要求 `audit.read`。查询使用显式 Prisma `select`，只返回事件 ID、请求追踪 ID、动作、目标类型/ID、结果、原因、时间及操作者姓名/邮箱；不得把 `beforeData`、`afterData`、`ipHash`、`actorId` 或数据库整行发送到管理前端。
- `/admin/logs` 使用服务端页码、每页数量、关键词、结果、操作者来源、目标类型和时间范围；MySQL 与 Sites 都返回筛选后的 `meta.total`、稳定目标类型分面和当前页白名单记录。页码上限 1000、每页上限 100，关键词和目标类型受长度约束，非法枚举失败关闭；管理页面默认 30 条一页并把筛选与页码保存在 URL。
- MySQL 审计响应使用 `Cache-Control: private, no-store`，Sites JSON 响应使用 `no-store`。详情只展示同一安全响应中的白名单字段；当前没有前后差异授权、IP 查看、导出、不可变归档或已批准保留期限，前端不得从数据库实际保存了差异和 IP 哈希推断这些能力已经开放。

### 数据安全就绪中心

- `/admin/data-security` 没有独立后端领域和写接口。页面使用当前管理员会话安全投影；只有拥有 `audit.read` 时才调用现有 `GET /v1/admin/audit?page=1&pageSize=100`，没有权限时审计计数、时间和记录保持受限且不得从缓存泄露。
- 当前页面可以说明仓库代码中已存在的联系方式 AES-256-GCM 认证加密与普通 SHA-256 规范化检索哈希、scrypt 密码派生、服务器保护的 TOTP 密钥、Valkey 会话、安全 Cookie、CSRF、MySQL RBAC 实时校验和 MySQL 审计；这些是代码控制证据，不是生产部署或合规认证。联系方式检索哈希当前不是 HMAC，不能把它描述为带密钥哈希。
- 当前会话只显示角色键数量、权限数量、TOTP 开关和 `audit.read` 是否授予。审计表只使用既有安全响应中的事件 ID、请求 ID、时间、动作、结果、操作者和目标，不读取前后差异、IP 哈希、联系方式密文/哈希、密码派生、TOTP 密钥、会话 ID、Cookie、CSRF Token、环境变量或数据库凭据。
- 公开目录、订单联系方式、管理员身份和审计证据是当前代码边界说明，不是已审批的数据分类政策；各边界的保留期限固定显示 `NOT_DEFINED`，不得恢复 30/365/90 天等未经批准的期限。
- 正式数据分类政策与保留调度为 `NOT_DEFINED`，删除/匿名化和隐私请求为 `NOT_IMPLEMENTED`，生产密钥管理为 `NOT_CONNECTED`。刷新只重读审计 GET，不得扫描、移动、删除、归档或修改任何数据。

### 机密配置就绪中心

- `/admin/secrets` 没有机密读取或写入 API。页面只使用仓库内固定模型呈现配置名、生产来源、消费任务和 `DEFINED_INFRA`、`NOT_DEPLOYED`、`NOT_IMPLEMENTED`、`NOT_DEFINED` 状态，不读取 `.env`、Secrets Manager、值、后缀、版本、创建时间或轮换时间。
- 当前 CDK 有四个机密来源：RDS 生成的数据库凭据、Valkey 认证 Secret、管理员会话 Secret 和应用数据加密 Secret；`DB_HOST`、`DB_USER`、`DB_PASSWORD`、`REDIS_PASSWORD`、`SESSION_SECRET`、`AUTH_ENCRYPTION_KEY` 六个绑定只进入 API ECS 任务，相关 Secret 只向 API Task Role 授予读取权限。前端 ECS 任务的机密绑定为 0。
- CDK `synth` 或资源定义不能证明 AWS 已部署、运行值存在、ECS 注入成功或密钥已经轮换。运行时无值元数据、自动轮换、兼容解密窗口、双版本回滚、客户管理 KMS Key、泄露处置与恢复手册必须保持关闭门禁，直到有独立实现和运行证据。
- `SESSION_SECRET` 只用于服务端会话 HMAC；`AUTH_ENCRYPTION_KEY` 当前同时用于订单联系方式与 TOTP 密钥的 AES-256-GCM 加密，尚未完成数据域分离。联系方式检索哈希为普通 SHA-256，不是 HMAC；拆分密钥前必须设计兼容读取、数据迁移和回滚。
- 管理页不得提供新增、查看、轮换、导出或复制机密值的前端按钮。未来机密变更属于高风险服务端工作，必须具备最近认证、最小权限、原因、审计、兼容解密和可验证回滚后再单独实施。

### 订单管理接口

- `GET /v1/admin/orders` 仅接受白名单分页、关键词、状态、负责人和联系渠道筛选；返回显式投影，不返回幂等键、联系方式密文或哈希。
- `GET /v1/admin/orders/:id` 返回订单快照、脱敏联系方式、负责人、完整状态时间线和服务端允许的下一状态。
- `GET /v1/admin/orders/assignees` 只返回状态为 `ACTIVE` 且通过角色拥有 `orders.write` 的管理员。
- `PATCH /v1/admin/orders/:id/status` 使用预期旧状态和预期更新时间做条件更新；订单状态、状态历史和审计必须在同一 Serializable 事务内成功或回滚。
- `PATCH /v1/admin/orders/:id/assignment` 使用预期旧负责人和预期更新时间防止覆盖，并在同一事务记录审计。
- `POST /v1/admin/orders/:id/reveal-contact` 要求 `contacts.reveal`、最近认证和业务原因，响应使用 `Cache-Control: no-store`；明文不得进入列表、审计差异、日志或通用前端缓存。
- 新版本创建且真实扣过有限库存的订单会保存 `inventoryReserved`。到期且仍为 `MANUAL_PENDING` 的订单在下一次商品、下单、工作台或订单访问前通过条件更新取消，并在同一 Serializable 事务写入 `inventoryReleasedAt`、返还一件库存、状态历史和 `order.reservation.expired` 审计；并发扫描只有一个能成功。
- 历史订单迁移默认 `inventoryReserved = false`，不会推断或返还历史库存。`CONTACTED` 及后续状态不自动到期取消；管理员通过合法状态机人工转为 `CANCELLED` 时，只有尚未释放的真实预留可以在同一事务返还一次。`PAYMENT_PROCESSING`、付款、履约、售后和争议状态没有任何自动资金或库存动作。
- 当前 `PAID`、`REFUNDED` 与 `DISPUTED` 是人工内部记录，不包含支付商回执、退款流水或独立争议案件。

### 人工售后订单视图

- `/admin/disputes` 只能读取状态为 `REFUND_PENDING`、`REFUNDED`、`DISPUTED` 的现有订单；读取要求 `orders.read`，负责人和状态写入要求 `orders.write`。
- 售后页面不得创建绕过订单服务的状态写入。合法下一状态来自订单 API，写入继续提交预期旧状态和预期更新时间，使用 CAS 防止覆盖，并让订单状态、状态历史和审计在同一 Serializable 事务中提交。
- 列表与详情继续使用订单显式字段投影和脱敏规则，不返回联系方式密文、哈希或幂等键；没有 `contacts.reveal` 和最近认证时不得显示完整联系方式。
- 该页面是人工订单状态视图，不是独立退款或争议案件系统。当前数据不能表示部分退款、申请金额、证据、双人审批、支付提供商回执、结算批次或真实资金动作。
- 不得把缺失的退款金额、外部流水、付款凭证或审批结果编码进自由文本原因并当作结构化数据；这些能力需要单独的领域模型、权限、迁移和验收。

### 人工收款记录

- `/admin/payments` 只读返回 `OrderStatusHistory.toStatus` 为 `PAID`、`REFUND_PENDING`、`REFUNDED`、`DISPUTED` 的人工事件。状态历史由现有订单服务只追加，收款接口和页面不得提供更新、删除或补写历史能力。
- 列表读取要求 `orders.read`；打开订单详情继续执行订单详情的权限投影，订单写入与完整联系方式揭示分别保留 `orders.write`、`contacts.reveal` 和最近认证要求。
- 每条事件使用状态历史 ID 作为稳定事件 ID，并显式返回 `externalActionVerified: false`。这个字段不能由前端覆盖，也不能因为订单当前状态、时间经过或管理员文案变为 `true`。
- 允许返回的业务字段限于事件类型、事件时间、记录人、原因、订单号、商品快照、订单金额和币种、参考金额和币种、汇率快照；不得返回联系方式密文、哈希、幂等键或其他支付凭据。
- 人工收款记录只证明内部状态被记录，不是支付流水或会计台账。当前系统没有实际到账金额、部分或多次付款/退款、手续费、税费、支付方式、外部交易 ID、凭证、结算批次、渠道对账或跨币种汇总。
- 金额统计只能按原始订单币种分组；不得从参考金额或汇率快照生成未经业务确认的跨币种总收入、余额、应收、已结算或利润。
- `/admin/reconciliation` 复用人工收款 GET 接口并遍历全部受限分页；读取要求 `orders.read`，页面没有写操作。前端必须验证所有事件仍为 `externalActionVerified: false`，异常真值整体失败关闭。
- 对账准备状态只允许按事件类型和原始币种统计记录数，不计算跨币种金额。支付商账单、银行流水、外部交易 ID、实际到账、手续费、税费、结算批次、匹配结果和差异均为未采集或未开发，不能从人工状态历史推断。

## 认证与权限

- 客户端保持无账户设计，不因此获得后台能力。
- 后台已独立认证，并在 API 层执行权限码授权；公开目录接口与 `/v1/admin/*` 权限边界分离。
- 后台主认证使用邮箱与经过 scrypt 派生存储的管理员密码。
- TOTP 默认为关闭状态；管理员可在安全中心开启或关闭。开启后，密码验证成功还必须完成 6 位动态码验证。
- 会话由服务端管理，只通过 `HttpOnly`、`Secure`、`SameSite` Cookie 关联；禁止将管理员 Token 写入 `localStorage` 或 `sessionStorage`。
- 无权限时界面隐藏或禁用操作，API 同时返回明确的权限错误。
- 成员角色与账号生命周期读取/写入使用 `team.manage`，角色读取、创建、双语资料编辑、权限编辑和删除使用 `roles.manage`；写入还要求五分钟内最近认证、至少 8 个字符的业务原因与客户端二次确认。
- 权限、角色资料、空角色删除和账号生命周期写入使用 `updatedAt` CAS 与 Serializable 事务，数据库状态与审计同时提交；角色创建也使用 Serializable 事务并在同一事务建立权限关系和审计。禁止管理员修改自己的角色或账号生命周期、移除最后一名正常超级管理员的系统角色、停用最后一名正常超级管理员，或修改 `SUPER_ADMIN` 的资料、权限和生命周期。
- 角色键只在创建时接受 3–80 位大写字母、数字和下划线且必须以字母开头，创建后不可修改；新角色至少需要一个数据库中已存在的权限。只有成员数为 0 的非系统角色可以删除，删除成功后由现有外键级联移除权限关系。
- 账号启用、停用、解锁和其他成员 TOTP 重置会在数据库更新前撤销目标成员全部 Valkey 会话及 TOTP 登录/绑定流程。启用只接受已有密码且至少分配一个角色的停用账号；TOTP 重置只记录布尔状态和撤销数量，不记录加密密钥。
- Sites 的成员身份、密码、TOTP 与会话由 ChatGPT 管理；CloudBridge 团队页只读显示身份来源，不调用 MySQL 生命周期写接口，未采集的平台 TOTP、失败登录与锁定数据不得显示为零或关闭。
- 受保护请求从 MySQL 重新派生当前账号状态和权限；账号不再正常时销毁会话，权限变化时同步 Valkey 会话快照并按新权限立即授权或拒绝。
- 登录、敏感查看、导出、权限修改、支付配置、退款和恢复操作必须支持会话控制、限速、重新认证、二次确认与审计。
- 当前本地密码登录、可选 TOTP、会话、RBAC 代码和类型检查是实现证据；仍需验证器真机、渗透测试和 AWS staging 联调才能形成发布证据。

## 敏感信息

- 联系方式默认脱敏；查看、复制和导出完整值属于敏感操作。
- 生产环境的敏感字段应加密存储，密钥与数据分离管理。
- 日志、错误、分析事件和通知内容不得包含密钥、Token、密码或不必要的完整个人信息。
- 测试数据使用明显的虚构值，不在仓库中保存真实客户信息。

## 支付与 Webhook

- 客户银行卡和钱包凭据只在合规第三方托管支付页收集；本站不提供卡号、有效期或 CVV 输入框。
- 支付密钥只显示是否配置、使用范围和末尾标识，不得返回或记录完整值。
- 正式启用支付需要重新认证、影响预览、二次确认与不可变审计记录。
- Webhook 必须验证签名、时间窗口和事件类型，按提供商事件 ID 幂等处理；重复事件返回成功但不重复执行业务。
- 事件延迟、签名失败、处理失败、重试耗尽和对账差异是独立告警状态。
- 退款、部分退款、拒付和争议采用独立状态机；审批人与申请人应分离。

## 当前备份定义与证据边界

- 在 MySQL/AWS 运行路径中，`/admin/backups` 不读取数据库、Docker、文件系统或 AWS，只展示仓库能够静态核对的定义。页面没有快照、导出、下载、删除、恢复或演练写操作。
- 在 Sites 运行路径中，同一路由读取真实 D1 备份记录，允许 `settings.write` 创建、重新校验、执行无写入的恢复包逻辑验证和发起隔离恢复演练，允许 `settings.read` 下载 R2 中的 AES-256-GCM 密文。逻辑验证检查快照主键、关联、JSON 和订单联系方式可解密性，不返回明文、不写当前 D1。
- 隔离演练为每次运行生成一次性 RSA 公私钥。Sites 服务器只把已通过校验的快照重新封装给该次公钥；本地恢复器在一次性内存 SQLite 中应用当前 migration、清空种子数据、导入全部快照表、逐表回读并执行 `PRAGMA foreign_key_check`。完成回传必须同时通过限时令牌、备份 SHA-256、运行结果字段和派生 HMAC 证明，伪造记录数或复用过期转移包会失败关闭。私钥和明文恢复库不上传，当前生产 D1 不被写入。可选 D1 候选会在本机生成包含 migration 与快照行的明文 `restore.sql`、`verify.sql`、校验清单和切换/回滚说明；写盘前会把同一 SQL 导入第二个空 SQLite 再核对，目录和文件固定为 `0700/0600` 且拒绝覆盖。
- Sites 备份页会派生最近备份、今日自动备份、失败/卡住记录、30 天内隔离 SQLite 演练和外部告警送达五项门禁。外部告警当前为 `NOT_CONNECTED`，`EXTERNAL_ALERT_DELIVERY` 固定失败；页面信号不能代替邮件、短信或 Telegram 送达证据，也不得在该门禁失败时显示完全就绪。
- 本地 MySQL 与 Valkey 使用同机 Docker 命名卷，Valkey 启用 AOF；这些配置支持容器或进程恢复，但不能抵抗卷删除、磁盘损坏或整机丢失，因此统一标记为 `NOT_A_BACKUP`。
- CDK 定义 RDS Multi-AZ、存储加密、7 天自动备份、删除保护、保留自动备份与资源 `RETAIN`，以及 Valkey 双节点 Multi-AZ、静态/传输加密、7 份快照和 `18:00-19:00` 窗口。AWS 尚未部署，因此这些只属于 `DEFINED_INFRA`，运行状态统一为 `NOT_DEPLOYED`。
- 当前没有 MySQL 导出或 Valkey 备份任务、离机/独立故障域副本、不可变副本、外部失败/过期告警、批准的 RPO/RTO 或独立 D1 切换演练。Sites 的内存恢复与候选 SQL 二次导入证明快照可以进入兼容 SQLite schema 并通过回读与外键检查，但候选不含 R2 对象和备份历史，也不证明另一套远程 D1 已创建或导入、管理员可登录、生产流量可切换或回滚已演练。

## 当前系统集成与任务证据边界

- `/admin/integrations` 只有三个现有读取来源：公开 `GET /v1/health`、受 `catalog.read` 保护的 `GET /v1/admin/currencies` 和受 `settings.read` 保护的 `GET /v1/admin/telegram-new-order-settings`。页面不拥有写接口，不执行连接测试、同步、重试、通知、支付、备份或部署。
- 健康接口并行执行 MySQL `SELECT 1` 与 Valkey `PING`，两项各有 1500ms 响应等待上限；仅当本次 API 请求和两项探测都成功时才返回 `healthy` / `connected`，任一失败或超时统一返回不含连接细节的 503。
- 健康响应只公开 MySQL/Valkey 稳定状态、本次非负整数耗时与时间戳。Promise 超时不能取消已提交给驱动的底层操作；这些耗时不是平均延迟、错误率、可用率、容量或 SLA，也不能证明对象存储、邮件、支付、汇率提供商、Telegram 或 AWS 健康。
- Valkey 探测复用 `SessionService` 已有连接，只执行 `PING`；集成页不读取会话、键值或缓存内容。币种与汇率来自现有 MySQL 管理记录，不能反推外部汇率提供商、定时同步或来源核验。
- Telegram 设置服务端固定派生 `NOT_CONNECTED`、`effectiveEnabled: false`、`tokenConfigured: false`、`externalDeliveryVerified: false`；媒体仅使用 `/assets/` 本地引用；CDK 中的 ECS、RDS、Valkey、ALB、WAF、CloudWatch 和访问日志桶只是未部署模板。
- 当前没有邮件提供商、支付提供商、外部汇率适配器、对象存储上传、队列、调度器、Worker、任务事件存储或统一集成观测。旧预览中的 99.99% 可用率、邮件重试数、30 分钟同步、任务时间、追踪编号和成功结果均不属于数据证据，已经删除。

## 数据治理与真实恢复（未来目标，当前未实现）

- 数据按公开、内部、个人和机密分级，为每类记录收集目的、访问范围、保留期、删除或匿名化规则。
- 完整联系方式默认脱敏；未来治理流程还应明确记录人员、时间、订单、设备和原因。
- 访问、更正、导出和删除请求进入有时限、有负责人、有结果证据的隐私请求流程。
- RDS 启用加密、自动备份和时间点恢复；设计目标为 RPO 不高于 5 分钟、核心服务 RTO 不高于 60 分钟。
- 每次恢复演练在隔离环境执行，验证订单、权限和对象完整性后销毁环境并归档证据。
- 数据库密码、支付密钥、Webhook 密钥和第三方 Token 只存于 Secrets Manager/KMS，应用按最小权限读取并定期轮换。

## 审计与外部操作

- 创建、更新、删除、启停、价格/库存调整、权限变更和敏感信息操作记录审计事件。
- 审计至少包含操作者、动作码、目标 ID、结果、时间、请求追踪 ID；高风险变更记录前后差异。
- 通知、支付、汇率和第三方集成必须保存真实外部结果或失败原因。
- 未连接、超时、排队、部分成功和失败是独立状态，不得合并显示为成功。

## Telegram 订单通知

- 当前准备阶段使用 `SiteSetting` 键 `notifications.telegram.new-order` 保存非密钥配置：`requestedEnabled`、`recipientGroupLabel`、固定 `ORDER_CREATED`、`includedFields`，并使用 `version` / `updatedAt` 做并发控制；不得借此保存 Bot Token、Chat ID 或发送记录。
- 配置 GET 要求 `settings.read`；配置 PUT 要求 `settings.write`、五分钟内最近认证和业务原因，并提交预期 `version` 做 CAS。配置写入和审计必须在同一 Serializable 事务内成功或回滚，审计只记录安全的前后差异。
- 服务端始终派生 `NOT_CONNECTED`、`effectiveEnabled: false`、`tokenConfigured: false`、`externalDeliveryVerified: false`；`requestedEnabled` 不能直接决定连接或实际启用状态。
- simulation POST 只能使用服务端固定虚构订单和字段白名单生成脱敏预览，必须返回 `deliveryAttempted: false`；不得接受真实订单 ID、真实联系方式、任意消息正文、Token 或 Chat ID，也不得请求 Telegram、排队、重试或写发送记录。
- `/admin/telegram-bot` 可以显示真实配置已保存，但必须持续显示未连接和未外部核验；`/admin/notifications` 只读同一配置并持续展示真实上线门禁，不得提供发送、已读、处理、失败重试或投递结果写入。
- 当前没有投递事件存储。发送时间、接收结果、未读数量、失败次数和重试状态属于未采集数据，页面和 API 不得把它们显示为零、成功或空历史结论。
- Telegram Bot Token 只能由未来服务端从 Secrets Manager/KMS 读取，不得放入前端、`VITE_` 环境变量、浏览器存储、日志或消息模板。
- 订单通知默认发送到内部管理群，机器人只申请发送消息所需的最小权限，不读取群历史，也不处理客户私聊。
- 推送内容使用字段白名单：订单号、商品、金额、币种、订单状态、创建时间、联系渠道、脱敏联系方式和后台订单链接。
- 完整联系方式、内部备注、付款凭据、登录信息、密钥和未脱敏个人信息禁止进入 Telegram 消息。
- 每个订单事件使用稳定事件 ID 和幂等键；Telegram 超时、限流、失败、排队和重试耗尽必须保留为独立状态。
- 发送记录至少保存目标群末尾标识、事件 ID、订单 ID、尝试次数、外部结果、追踪 ID 和时间，不保存 Bot Token 或不必要的个人数据。
- 启用、停用、变更目标群和轮换机器人凭据需要重新认证、影响预览、二次确认与审计。
