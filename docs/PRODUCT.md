# CloudBridge 产品范围与能力状态

## 产品定位

CloudBridge 是一个中英文 AI 服务商品展示与人工联系下单平台。客户端用于浏览、筛选、搜索、查看价格和提交单一联系方式；管理后台用于管理商品、分类、币种、人工订单与安全审计。

客户端与管理后台是独立应用。客户端不提供商城账户、登录、购物车或数量选择器；后台使用邮箱与密码登录，可选 TOTP 双重验证，并使用服务端会话、权限码和审计。

## 能力状态定义

- **当前已实现**：主平台代码和本地依赖中存在可运行、可测试的真实逻辑或持久化。
- **当前模拟**：遗留原型或设计页使用静态数据、浏览器存储或前端延时，不产生服务端结果。
- **未来规划**：目标架构或生产能力，当前代码和环境不保证存在。

文案、验收和交付报告必须使用以上状态，不得用“页面能点”替代真实业务证据。

## 当前能力矩阵

| 能力 | 当前状态 | 当前证据与边界 |
| --- | --- | --- |
| 商品展示、双语切换、币种切换 | 当前已实现 | Next.js 客户端从 NestJS/MySQL 读取目录与汇率；种子汇率不等于实时市场数据 |
| 商品名称模糊搜索、单选分类筛选 | 当前已实现 | API 按当前语言在 MySQL 中执行受控模糊匹配，可组合分类 |
| 分类排序、显示状态、商品归类 | 当前已实现 | 管理后台通过 RBAC API 写入 MySQL，并使用版本号防止覆盖并发修改 |
| 联系方式下单与订单凭证 | 当前已实现 | API 校验服务器价格/库存/政策，联系方式加密，幂等创建 `MANUAL_PENDING` 订单；不代表已付款 |
| WhatsApp、Email、Telegram、QQ、微信联系配置 | 当前已实现/未来规划 | 联系渠道从数据库读取；真实客服响应和外部送达仍需运营证据 |

| 管理后台商品、分类、订单、汇率 | 当前已实现 | 本地独立管理应用与受权限保护 API；尚未部署 AWS |
| Telegram 新订单机器人 | 当前模拟 | 管理后台包含连接、脱敏消息模板、模拟测试、失败重试与审计设计；不保存 Bot Token，也不请求 Telegram |
| 管理员登录、MFA、会话、角色、权限和审计 | 当前已实现 | 密码主登录、可选 TOTP 双重验证、安全 Cookie、CSRF、RBAC 与 MySQL 审计已编码；TOTP 默认关闭 |
| 支付、对账、退款、争议与 Webhook | 当前模拟 | 只显示测试/关闭状态、健康证据和敏感操作确认，不连接提供商 |
| 数据分类、保留删除、备份恢复、机密和安全事件 | 当前模拟/未来规划 | 本地加密和审计已实现；AWS 备份恢复和告警尚无环境证据 |
| AWS staging | 未来规划 | CDK 模板已通过 synth，但未创建任何计费资源 |

## 客户端规则

- 首页保持首屏品牌轮播和商品陈列；搜索和分类只属于商品陈列区。
- 搜索对当前语言及官方产品名称做不区分大小写的模糊匹配，并可与一个分类组合筛选。
- 分类由后台管理中英文名称、启停、顺序和商品归属；稳定 ID 不因改名或排序改变。
- 语言与币种独立切换。中文界面只出现中文界面文案，英文界面只出现英文界面文案；官方专名、产品名、币种代码和机器标识保留原值。
- 下单只收集一种联系渠道及对应值，不增加账户、购物车或数量。
- 在线支付关闭时，只能生成“待人工确认”订单，不显示支付步骤。
- 不提供公开订单查询。客户保留订单凭证并通过客服处理，避免订单号与联系方式枚举。
- 正式隐私、服务、交付、退款及 Cookie 页面必须保持独立，设计稿上线前仍需业务与法律审核。
- 商品售罄、低库存、加载、无结果和错误状态必须有明确反馈，不能只靠颜色表达。
- 页头与页脚品牌区复用同一 CloudBridge Logo 和横向结构，只允许针对所在容器调整尺寸；图片不得拉伸，品牌主名称下不显示副标题。

## 管理后台规则

- 后台负责商品、分类、双语内容、价格、库存、币种、客服渠道和订单工作流。
- 后台设计稿覆盖九个一级入口和 24 个页面。未接入 API 的页面只用于评审布局、状态和交互，必须持续显示设计预览标识；其按钮、筛选和开关不得解释为业务功能已完成。
- 每个后台页面只有一个当前页标题，由顶栏持有；内容区直接进入真实数据或任务控件。
- 任何“保存成功”“汇率已更新”“权限已生效”都必须对应 API 的真实结果；通知未接通时必须标记未连接。
- 后台使用邮箱与密码主登录；管理员可在安全中心开启或关闭 TOTP，默认关闭。管理员 Token 不写入 `localStorage` 或 `sessionStorage`。
- 会话使用 Valkey 与 `HttpOnly`、`Secure`、`SameSite=Strict` Cookie；API 同时执行 CSRF 和权限码校验。
- 揭示联系方式、支付启停、退款、权限、导出和恢复操作必须设计拒绝、原因、重新认证、二次确认与审计状态。
- Telegram 机器人默认推送到内部订单管理群；只允许订单号、商品、金额、币种、状态、创建时间、联系方式渠道和脱敏联系方式进入消息模板。
- Telegram 连接配置属于敏感操作，必须重新认证并记录审计；原型测试结果必须明确标记为模拟，不能写成已真实发送。
- 所有后台结构化数据表一条记录只占一行。订单号、订单时间、商品、金额与 USDT、联系渠道、脱敏联系账号、处理状态、付款状态、负责人和操作必须使用独立列；其他表中的名称、代码、工作组、时间、事件 ID 和追踪信息遵循同一规则。
- 窄屏不把数据表转换为多行卡片，也不隐藏关键列；表格在自己的容器内横向滑动，订单号与操作列可保持吸附，超长内容用省略号和完整说明兼顾扫描效率与可访问性。
- 后台侧栏、登录页和品牌预览与客户端复用同一 CloudBridge Logo；只调整容器尺寸并保持原始宽高比，不显示“云桥管理中心”“Operations console”或其他 Logo 副标题。

## 明确不做

- 当前阶段不接入真实支付、Telegram 发送、生产通知或生产数据。
- 未确认费用、域名和证书前不执行 AWS `deploy`。
- 不从其他项目复制业务模块、角色代码、路由、接口字段、数据库结构、端口或部署脚本。
- 不因未来规划提前引入消息队列或媒体对象存储。
