# CloudBridge 产品范围与能力状态

## 产品定位

CloudBridge 是一个中英文 AI 服务商品展示与人工联系下单平台。客户端用于浏览、筛选、搜索、查看价格和提交单一联系方式；管理后台用于管理商品、分类、币种、人工订单与安全审计。

客户端与管理后台是独立应用。客户端不提供商城账户、登录、购物车或数量选择器；后台使用邮箱与密码登录，可选 TOTP 双重验证，并使用服务端会话、权限码和审计。

## 能力状态定义

- **当前已实现**：主平台代码和本地依赖中存在可运行、可测试的真实逻辑或持久化。
- **当前模拟**：遗留原型或设计页使用静态数据、浏览器存储或前端延时，不产生服务端结果。
- **未来规划**：目标架构或生产能力，当前代码和环境不保证存在。

文案、验收和交付报告必须使用以上状态，不得用“页面能点”替代真实业务证据。

## 客户端规则

- 首页保持首屏品牌轮播和商品陈列；搜索和分类只属于商品陈列区。
- 搜索对当前语言及官方产品名称做不区分大小写的模糊匹配，并可与一个分类组合筛选。
- 分类由后台管理中英文名称、启停、顺序和商品归属；稳定 ID 不因改名或排序改变。
- 语言与币种独立切换。中文界面只出现中文界面文案，英文界面只出现英文界面文案；官方专名、产品名、币种代码和机器标识保留原值。
- 下单只收集一种联系渠道及对应值，不增加账户、购物车或数量。
- 在线支付关闭时，只能生成“待人工确认”订单，不显示支付步骤。
- 不提供公开订单查询。客户保留订单凭证并通过客服处理，避免订单号与联系方式枚举。
- 正式隐私、服务、交付、退款及 Cookie 页面必须保持独立，设计稿上线前仍需业务与法律审核。
- 商品售罄、低库存、加载、无结果和错误状态必须有明确反馈，不能只靠颜色表达。
- 页头与页脚品牌区复用同一 CloudBridge Logo 和横向结构，只允许针对所在容器调整尺寸；图片不得拉伸，品牌主名称下不显示副标题。

## 管理后台规则

- 后台负责商品、分类、双语内容、价格、库存、币种、客服渠道和订单工作流。
- `/admin/categories` 读取真实 MySQL 分类并把写入入口严格绑定 `catalog.write`；只有 `catalog.read` 的账号仍可查看分类和影响概览，但不能看到新增或编辑操作。
- 分类影响概览只统计当前分类接口返回的非归档分类、商品关联、顺序和双语完整度。非启用分类会退出公开筛选导航，但不会自动隐藏、移动或删除关联商品；归档分类也会退出当前管理列表。
- `/admin/products` 读取真实 MySQL 商品并把新增、编辑与保存入口严格绑定 `catalog.write`；只有 `catalog.read` 的账号仍可搜索商品和查看库存与上架概览，但不能看到写操作。
- 商品概览只统计当前搜索结果第一页（最多 100 条）并与单独加载的非归档分类列表交叉检查。公开列表只读取 `ACTIVE` 商品；前台现有规则把有限库存 0 显示为售罄、1–3 显示低库存。该投影不是全库库存、库存流水、预留返库、阈值告警或发布记录。
- `/admin/dashboard` 的四项主指标与最近订单来自现有 `GET /v1/admin/overview`。最近订单最多六条，只是样本而不是订单总数；未启用商品只能由商品总数减去启用数确定性派生。
- 工作台没有提醒运行证据时必须显示 `NOT_COLLECTED` 或 `NOT_IMPLEMENTED`。库存预留返库、低库存阈值聚合、通知失败数量和自动安全告警不得用硬编码数量、零值或设计流程伪装为已运行。
- 订单中心的列表、详情、负责人和状态时间线读取真实 MySQL 数据；客户端只能选择服务端返回的合法下一状态，状态、历史和审计在同一事务内提交，并以旧状态和更新时间防止并发覆盖。
- 订单的付款、退款和争议状态只表示管理员人工记录。没有外部支付、退款或争议证据时，不得将这些状态解释为资金动作已经自动完成。
- `/admin/disputes` 的实施目标是从同一订单数据中集中展示 `REFUND_PENDING`、`REFUNDED`、`DISPUTED`，并复用 `orders.read`、`orders.write`、订单状态机、CAS 并发控制和事务审计；不得另造一套前端售后状态。
- 人工售后订单视图不提供独立退款申请金额、部分退款、证据、双人审批、支付商回执或资金结算能力；需要这些能力时必须单独确认领域模型、安全规则和数据库变更。
- `/admin/payments` 只读展示 `OrderStatusHistory.toStatus` 为 `PAID`、`REFUND_PENDING`、`REFUNDED`、`DISPUTED` 的人工事件；读取要求 `orders.read`，打开订单详情继续沿用原订单权限，收款页不得修改订单或事件。
- 人工收款记录不是支付流水或会计台账，每条事件必须显示 `externalActionVerified: false`；没有实际到账、部分或多次付款/退款、手续费、税费、支付方式、外部 ID、凭证、结算批次、对账或跨币种汇总能力。
- `/admin/reconciliation` 是 `orders.read` 保护的只读准备状态：读取全部人工收款事件，只按原始币种统计记录数并最多展示八条最近内部记录；没有读取权限时不得请求接口。
- 对账准备中心中的 `NOT_COLLECTED` 表示外部证据不存在于当前系统，不等于金额为 0；`NOT_IMPLEMENTED` 表示对应支付连接、Webhook 或匹配流程尚未开发。人工状态历史不能解释为渠道账单、银行流水、实际到账、结算结果或差异证据。
- `/admin/media` 是现有商品与首页轮播记录的只读前端聚合，不拥有媒体表、文件上传 API 或存储写权限。商品使用 `catalog.read`，首页轮播使用 `content.read`；缺少其中一种权限时只显示获准范围。
- 媒体引用清单只证明 MySQL 记录引用了某个路径以及当前浏览器可以或不可以加载该地址，不证明文件大小、内容安全、优化状态、未引用文件、对象存储同步或生产 CDN 可用。
- `/admin/team` 真实读取管理员的安全白名单字段与角色；角色分配要求 `team.manage`、最近认证、业务原因、二次确认、CAS 与事务审计。管理员不能修改自己的角色，最后一名正常超级管理员不能被降权。
- `/admin/roles` 真实读取权限矩阵；修改非系统角色要求 `roles.manage`、最近认证、业务原因、二次确认、CAS 与事务审计。`SUPER_ADMIN` 的全部权限由系统保护，当前不提供角色新建、删除或名称编辑。
- `/admin/translations` 只聚合当前账号有权读取的五类双语内容；商品/分类、轮播、客服渠道和站点设置分别沿用 `catalog`、`content`、`support`、`settings` 的读写权限与所属 API，不提供跨模块通用写权限。
- 双语内容保存要求中文和英文都非空并服从所属字段长度；不跨语言回退。站点设置继续要求业务原因和版本 CAS，其他实体继续沿用各自版本 CAS；并发或权限拒绝不能伪装成保存成功。
- `/admin/logs` 读取受 `audit.read` 保护的真实审计 API，当前加载最新 100 条及数据库记录总数，并在已加载窗口内提供关键词、结果、操作来源、目标类型和时间筛选以及安全详情。
- 审计 API 对管理前端只返回事件 ID、追踪 ID、时间、动作、结果、操作者姓名/邮箱、目标类型/ID 和原因；数据库中的前后快照、IP 哈希、操作者内部 ID 与整行数据不得进入响应。当前没有导出、完整历史翻页、正式保留策略或差异查看。
- `/admin/security-events` 复用 `audit.read` 与现有审计 API，只挑选登录认证、角色权限、敏感联系方式、关键设置以及全部拒绝记录；普通成功的商品或内容编辑不进入安全信号。
- 安全信号的“优先复核/常规复核/信息记录”是前端固定规则，不是机器学习、关联检测或外部威胁情报结果。页面不提供自动告警、账号锁定、会话撤销、事件指派、结案或导出。
- `/admin/data-security` 是只读就绪中心：无论是否拥有 `audit.read` 都可查看非敏感代码边界和当前会话安全投影；只有获得 `audit.read` 时才请求最近 100 条审计记录，没有权限时不得发起该请求。
- 数据安全页面中的 `IMPLEMENTED_CODE` 只证明仓库存在相应代码与自动测试，`NOT_DEFINED`、`NOT_IMPLEMENTED`、`NOT_CONNECTED` 分别表示尚无批准规则、尚未开发或尚未连接。页面不创建保留、删除、匿名化、隐私请求、KMS、备份或合规结果。
- `/admin/secrets` 是无值只读就绪中心：只投影 `.env.example`、API 使用代码和 AWS CDK 中能够核对的配置名、来源、消费边界与门禁，不读取本地 `.env` 或 Secrets Manager，也不显示密钥值、后缀、版本、创建时间或轮换成功。
- CDK 当前定义 RDS 生成凭据、Valkey、管理员会话和应用加密四个机密来源，以及只注入 API ECS 任务的六个绑定；这只属于 `DEFINED_INFRA` 代码证据。AWS 尚未部署，运行时元数据接口、自动轮换、双版本回滚、客户管理 KMS Key 和泄露处置手册尚未具备。
- `AUTH_ENCRYPTION_KEY` 当前同时保护订单联系方式与 TOTP 密钥，数据域尚未分离；联系方式检索使用普通 SHA-256 规范化哈希，不是 HMAC。页面不得用伪造的 Stripe 密钥、后缀或轮换天数掩盖这些缺口。
- `/admin/backups` 是无运行查询的只读就绪中心：只投影 `compose.yaml` 与 CDK 中能够核对的资源定义和关闭门禁，不读取 MySQL、Valkey、Docker 卷、文件系统或 AWS，也不提供创建快照、下载、删除或恢复操作。
- 本地 `cloudbridge_mysql` 和 `cloudbridge_redis` 命名卷只代表同机持久化，Valkey AOF 也不是离机备份；页面必须把它们标记为 `NOT_A_BACKUP`，不能显示最近成功时间、文件大小、校验和、保留期或可恢复结论。
- CDK 中 RDS 7 天自动备份、删除保护和 `RETAIN`，以及 Valkey 7 份快照和固定窗口只属于 `DEFINED_INFRA`；AWS 未部署时必须保持 `NOT_DEPLOYED`，RPO/RTO 与恢复完整性在真实演练前不得写成已达成。
- `/admin/integrations` 是真实只读集成边界页：公开健康接口只证明本次 API 请求、MySQL `SELECT 1` 与 Valkey `PING` 在各自 1500ms 上限内完成；`catalog.read` 才读取币种与已保存汇率，`settings.read` 才读取 Telegram 配置，无权限时不得发起相应请求。
- 集成页中的币种与汇率是管理员维护的 MySQL 记录，不是外部提供商同步；Telegram 保持 `NOT_CONNECTED`，Valkey 仅在本次健康请求中标记 `RUNTIME_VERIFIED`，本地 `/assets/` 不得写成对象存储，CDK 模板不得写成 AWS 已部署。
- 当前已接通外部服务和已实现后台任务均为 0。没有邮件、支付、外部汇率、对象存储、调度器、队列、Worker、任务事件或统一集成可观测性时，不得恢复成功率、重试数、计划时间、追踪编号或健康结论。
- 后台守卫在每次受保护请求重新读取 MySQL 中的账号状态与有效权限；账号被停用或权限被撤销后，旧 Valkey 会话不能继续依赖缓存权限访问。
- 完整联系方式默认不返回；具备独立权限的管理员还必须处于最近认证窗口、填写业务原因并确认，明文只在订单详情内短时显示。
- `/admin/telegram-bot` 使用 `SiteSetting` 键 `notifications.telegram.new-order` 真实保存 `requestedEnabled`、内部群名称、固定 `ORDER_CREATED` 事件和字段白名单；它不保存 Bot Token 或 Chat ID，群名称和业务原因也拒绝夹带疑似 Token 或 Chat ID。
- Telegram 配置读取要求 `settings.read`；保存要求 `settings.write`、五分钟内最近认证、业务原因、版本 CAS 和事务审计。请求启用不等于实际启用，服务端始终派生 `NOT_CONNECTED`、`effectiveEnabled: false`、`tokenConfigured: false`、`externalDeliveryVerified: false`。
- Telegram 持久化配置损坏时整体失败关闭；未来时间的最近认证时间戳被拒绝，版本号限制在安全整数范围。
- Telegram simulation 只使用服务端固定虚构订单生成最多 8 个白名单字段的脱敏预览，示例联系方式为 `de***@invalid.example`，始终 `deliveryAttempted: false`，不发送、不重试、不排队、不写发送记录。
- `/admin/notifications` 与 `/admin/telegram-bot` 复用同一只读配置缓存；通知中心只判断真实上线门槛，没有投递事件存储时必须显示“未采集 / Not collected”，不能显示未读数、失败数、发送结果或重试状态。
- 后台九个一级入口和 24 个页面均已进入真实或明确受限状态，独立设计预览路由已经删除。明确受限页面仍必须直接展示未开发、未连接、未部署或无权限状态，不能用模拟成功、按钮反馈或虚构记录代替实现证据。
- 每个后台页面只有一个当前页标题，由顶栏持有；内容区直接进入真实数据或任务控件。
- 任何“保存成功”“汇率已更新”“权限已生效”都必须对应 API 的真实结果；通知未接通时必须标记未连接。
- 后台使用邮箱与密码主登录；管理员可在安全中心开启或关闭 TOTP，默认关闭。管理员 Token 不写入 `localStorage` 或 `sessionStorage`。
- 会话使用 Valkey 与 `HttpOnly`、`Secure`、`SameSite=Strict` Cookie；API 同时执行 CSRF 和权限码校验。
- 揭示联系方式、支付启停、退款、权限、导出和恢复操作必须设计拒绝、原因、重新认证、二次确认与审计状态。
- 未来真实接通 Telegram 时，目标是推送到用户确认的内部订单管理群；只允许订单号、商品、金额、币种、状态、创建时间、联系方式渠道和脱敏联系方式进入消息模板。
- Telegram 连接配置属于敏感操作，必须重新认证并记录审计；原型测试结果必须明确标记为模拟，不能写成已真实发送。
- 所有后台结构化数据表一条记录只占一行。订单号、订单时间、商品、金额与 USDT、联系渠道、脱敏联系账号、处理状态、付款状态、负责人和操作必须使用独立列；其他表中的名称、代码、工作组、时间、事件 ID 和追踪信息遵循同一规则。
- 窄屏不把数据表转换为多行卡片，也不隐藏关键列；表格在自己的容器内横向滑动，订单号与操作列可保持吸附，超长内容用省略号和完整说明兼顾扫描效率与可访问性。
- 后台侧栏、登录页和品牌预览与客户端复用同一 CloudBridge Logo；只调整容器尺寸并保持原始宽高比，不显示“云桥管理中心”“Operations console”或其他 Logo 副标题。
