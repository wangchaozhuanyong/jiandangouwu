# CloudBridge 产品范围

CloudBridge 是中英文 AI 工具服务展示与人工联系下单平台。生产架构保持 Sites-only：`apps/sites` 是唯一生产 Worker，结构化数据使用 Sites D1，媒体使用 Sites R2，管理员身份由 ChatGPT 托管。

本文把产品状态严格分为三层：

1. **现有真实**：已有生产代码、正式 API 或 D1 模型，并且仍需以部署状态和匿名访问证据判断是否已经上线。
2. **阶段一模拟预览**：只验证页面结构、视觉、文案、响应式和交互意图；使用 mock 或只读数据，服务端数据不变，不代表正式功能。
3. **阶段二以后**：需要正式路由、契约、D1 迁移、API、后台配置、测试和部署证据后才可对外启用。

页面可点击、模拟预览、本地测试和构建都不能替代真实接口、外部回执或生产部署证据。

## 现有真实能力（已实现）

### 客户端

- 当前公开路由为首页、商品详情、服务条款和隐私政策；当前正式页头只链接已有页面。
- 公开商品、单一分类归属、Hero 轮播、币种、商品名称搜索和单选分类筛选。
- Hero 支持后台新增、编辑、排序和启停；当前没有“关闭后收起首页 Hero 区域”的持久化布局设置。
- 首页按 Hero、四项能力栏、商品目录的顺序展示；当前商品目录不是桌面左侧分类、右侧商品布局。
- 首页右下角“中转站服务”是一个独立外部 HTTPS 入口，不是站内订阅页面；未配置地址时只显示真实不可用提示。
- 商品详情提供单商品人工下单，客户只填写一个联系渠道和联系方式。服务端重新校验价格、汇率、库存、政策版本和接单门禁，并使用幂等键防止重复创建。
- 商品详情支持图片覆盖式返回与分享、滚动后不透明导航栏、移动端渠道底部弹层，以及后台可配置的双语分享文案。
- 客户端支持完整中英文、币种独立选择和深浅主题；深色“夜航画廊”保持默认，浅色“瓷白双港”是正式组件视觉基线。
- 微信客服二维码使用后台上传的真实 PNG/JPEG/WebP 文件并存入 Sites R2；客户端可查看原图、复制微信号，并调用系统分享/保存或下载回退。
- 客户端没有账号、会员、购物车、数量选择器、自动发货和公开订单查询。

### 管理与运维

- 后台商品、分类、Hero、媒体、翻译、联系方式、客服、接单门禁、订单、审计和员工访问管理。
- 四个固定业务角色：所有者、运营员工、客服员工和只读员工。员工采用精确邮箱预授权，首次用同一 ChatGPT 邮箱登录时激活；系统不发送邀请邮件，也不保存员工密码。
- Telegram 真实通知队列：中文订单状态、发送时解密完整联系方式、幂等、六档重试、真实回执和人工重试。
- 自动运维告警：高优先级安全审计信号、备份创建失败和备份卡住记录使用独立 D1 队列，消息只包含脱敏元数据，并保存 Telegram 回执、失败状态与人工重试审计。
- ECB 法币与 Coinbase USDT/MYR 自动汇率；逐币种 AUTO/MANUAL、异常波动拒绝和陈旧失败关闭。
- D1 备份、隔离恢复演练与人工批准恢复。
- 保留策略草案、清理预览、隐私请求、HMAC 查询哈希、版本化密文和双密钥轮换。

## 阶段一模拟预览范围

阶段一只在前台 `/preview/v2/{locale}...`（例如 `/preview/v2/zh`）和后台 `/admin/__preview/v2/...` 隔离入口建立 V2 可评审界面样板，遵循 [V2 阶段一界面预览规范](V2_PREVIEW_SPEC.md)。允许预览：

- 四个频道入口：`首页 / Home`、`中转站订阅 / Transit subscriptions`、`AI 软件代充 / AI software recharge`、`Skill 推荐 / Skill recommendations`；另有独立的 DEMO 订单查询入口，仅模拟“订单号 + 下单联系方式”双字段验证。
- Hero 启用与完全收起两种视觉状态；首页与 Skill 移动端顶部图片使用横向比例，收起时不得保留骨架或占位高度。
- 两级商品分类样板：顶部一级分类横栏、左侧二级分类、右侧商品区；紧凑移动端保留顶部一级分类，并使用左侧纯文字二级分类栏和右侧横向商品列表。`全部商品` 仅是前台虚拟入口，DEMO 商品最终只归属二级分类。
- 商品网格验收目标：1440px 五列，1024px 与 768px 两列；390px 与 320px 为左栏旁的单列横卡。
- 中转站订阅、AI 软件代充专题页的内容层级、筛选和商品陈列样板。
- Skill 推荐页的内容分类、简介、来源说明和安全 GitHub 外链样板。
- 顶部网站导航与左侧商品分类分离；移动端页头保留主题、语言与客服，不显示购物车，使用首页、Skill 推荐、购物车、订单查询四项底部导航。
- 只保存在 React 内存中的 DEMO 购物车、不同商品去重、桌面右侧抽屉、移动端独立购物车页面与非提交式人工订单校验。
- 首页只保留横向 Hero 与商品目录，不显示频道卡、保障、流程、FAQ 或页脚；其他预览页面继续保留页脚。商品搜索与币种同排，目录到位后分类与商品列表独立滚动。
- 商品卡除购物车按钮外整卡进入详情；详情页复用同一图片来源和 1:1 图片框。订单查询页顶部不设置图片区域。
- 订单号加下单联系方式的安全查询界面样板；只使用 DEMO Fixture，不读取真实订单。
- 后台 `/admin/__preview/v2/categories` 两级分类管理样板，以及商品编辑中的一级到二级级联选择；所有新增、编辑、排序和状态只保存在 React 内存。

所有阶段一页面必须持续显示双语“界面设计预览”标识，明确说明使用模拟或只读数据、不会修改服务器数据。阶段一不得出现伪造的保存、订阅、安装、付款、发货、查单或成功回执。

阶段一的导航、Hero 状态和专题内容即使可交互，也不等于生产路由、后台设置或正式业务能力。现有外部“中转站服务”入口与预览中的“中转站订阅”是两个不同概念，不得混写。

## 阶段二以后正式实现候选

阶段二是否开工以再次确认后的 [V2 阶段二以后重构计划](V2_REFACTOR_PLAN.md) 为准。候选范围包括：

- 正式建立三个新专题路由及其双语 SEO、加载、错误、空状态和权限边界。
- 为统一商品库增加独立展示位置或专题集合，使同一商品可以被分配到首页、中转站订阅和 AI 软件代充，而不复制商品记录。
- 为现有分类增加可空 `parent_id`，正式接口限制最多两级，商品只引用二级分类；保留现有分类 ID 和商品关联，通过新增一级分类并回填父级完成兼容迁移。
- 为首页增加正式 Hero 显示开关和布局设置，并由后台保存、审计和版本冲突保护。
- 建立独立的 Skill 分类、Skill 内容、来源和 GitHub 链接模型；Skill 推荐不冒充可购买商品，也不提供自动安装。
- 为新模型补齐 D1 迁移、共享契约、公开和后台 API、管理界面、权限、审计、测试、发布与回滚证据。

上述正式候选仍不包含生产购物车、数量、多商品订单、支付、会员或自动发货；阶段一内存购物车不改变此边界。真实订单查询属于独立候选，只有完成双字段验证、HMAC、D1 防刷、统一失败响应和再次授权后才能实施。

## 当前生产门禁

公开浏览允许。真实联系方式未配置前，客服和接单保持关闭。启用顺序固定为：

1. 后台填写并启用至少一个真实联系方式。
2. 开启客服。
3. 开启接单。

自动清理保持关闭；密钥轮换只有在 `CLOUDBRIDGE_DATA_KEY_NEXT` 已配置时可执行。

自动告警复用已完成真实连接验证且有效启用的 Telegram 管理群。代码具备队列不等于当前通道已就绪；后台只有在服务端密钥、真实连接验证和启用状态同时满足时才显示 `CONNECTED`，备份外部告警门禁还要求至少一次该范围的真实消息回执。

## 明确暂缓或禁止擅自加入

- 线上支付、支付 Webhook、自动退款、资金结算和外部对账。
- 购物车、数量选择器、多商品订单和 `order_items`。
- 客户账号、登录、会员、积分、优惠券和跨设备购物数据。
- 自动发货、自动履约、自动订阅开通和自动续费。
- 公开订单查询，包括订单号加联系方式查询和随机 Token 查询。
- 自有域名。
- 无人确认的 D1 自动切换或自动回滚。
- 自动删除生产数据；当前只允许清理预览。
- 邮件邀请投递和跨账号会话管理。当前员工能力是 CloudBridge 内部邮箱预授权，不等于邮件邀请或 ChatGPT 跨账号会话。

这些范围只有在所有者再次明确授权，并完成数据、安全、权限和回滚设计后才能进入开发。
